# 調査(打撃側): なぜスマホで打てないか(baseball-game v3 / ゲート2 不合格の診断)

- 日付: 2026-10-27
- ステータス: 完了(ただし「実機・実走行の観察」は下の「0. 調査方法と限界」のとおり未実施。計算と既存画像による診断)
- 対象: `sample-app/frontend/src/features/baseball/`(worktree HEAD。v2 修正設計 H0〜H13 を実装した版。2026-10-20 に一度ゲート2を承認した版)
- 背景: 自動テスト(ボット B の安打率 33.2%)は合格していたが、人間がスマホで遊ぶと「打てない」「パワプロとは程遠い」と不合格になった。**自動テストの数値は人間の根拠にしない**。人間の目線で何が足りないかを一次情報で調べる。設計・実装判断はしない(選択肢の整理まで)。
- 同一指摘の繰り返しを避けるため、前回の診断 [`../baseball-game/2026-10-13-feel-diagnosis.md`](../baseball-game/2026-10-13-feel-diagnosis.md) と設計書「修正設計」の内容(到達ずれ・遅延補正・縦長カメラ・タップでスイング・曲がりの向き・影・判定のボール半径)は**既に直っている前提**で、「直した後でもなお残っている/新しく出た」問題だけを挙げる。

凡例: **[計算]** = コードの式と投影を手で計算した値(下の 2 フレームの実画面と ±2px で一致を確認)。**[画像]** = 既存の連写画像から読んだ値。**[コード]** = ソースを読んで確定した事実。**[推測]** = 根拠から考えた推測(人間の知覚・行動に関わるもの)。

## 0. 調査方法と限界(最初に読むこと)

1. **この調査セッションでは Bash が使えず、ゲームを実際に動かして連写することができなかった**(利用できたツールは Read/Grep/Glob/Write/WebSearch/WebFetch のみ)。依頼にあった「Playwright で 1 球ずつ連写して観察」は**未実施**。代わりに次を使った。
   - 現行コードの式(`path/pitch-path.ts`・`camera/rig.ts`・`space/params.ts`・`batting/*`・`hooks/usePointerInput.ts` ほか)を読み、ボールの画面位置・径・速さを手計算した。**計算値は、同じコードで撮られた実画面の連写(scratchpad `h12/shots/bat-844-D-400.png` のボール (218,285)・径約26px、`bat-844-D-200.png` の (237,355)・径約38px)と、位置 ±2px・径 ±1px で一致した**(計算では (219,286)・25.4px、(236,355)・37.1px)。そのため以降の計算値は実画面とほぼ同じとみなす。
   - 既存の連写画像(`docs/tests/assets/2026-10-19-baseball-game-feel-test/` と scratchpad `h12/shots/`・`pv3-game.png`)を目視した。
   - **画像の保存**: Write は文字しか書けずファイルをコピーできないため、PNG/JPG を `assets/` に保存できなかった。代わりに計算値から描いた SVG 2 枚を保存した([`assets/ball-path-390x844.svg`](assets/ball-path-390x844.svg)、[`assets/ball-speed-chart.svg`](assets/ball-speed-chart.svg))。実画像は既にリポジトリにある jpg を相対パスで参照し、リポジトリ外(scratchpad)にしかない画像は絶対パスを書いた(コピーが要る場合は Bash を使える担当に依頼してほしい)。
2. **パワプロの一次情報は WebSearch の要約だけ**で、ページ本文は読めていない(WebFetch がこの環境で名前解決に失敗し、全 URL で `getaddrinfo ENOTFOUND`)。公式 URL は検索結果に出たものを載せたが、本文の逐語確認は未了。公式の記述と攻略記事の記述は分けて書いた。
3. 人間の知覚・行動(「ここで迷う」「この合図は使えない」)は**推測**で、実測の人間データは無い。**スマホでの実際の試遊ログ(スイング時刻・カーソルの位置・結果)が一次データとして最も欲しい**(「5. 未確認事項」)。

## 1. 結論: 打撃側の不足トップ10(影響度順)

要旨: 現行は「**着弾点がどこか事前に分からず、ボールが見える頃にはカーソルを動かす時間が残っておらず、いつ振るかの先行合図もなく、操作の仕方の説明もない**」ゲームになっている。ボット試算(33%)は、ボットが**着弾点を完全に推定でき、到達時刻を完全に知覚し、ストライクだけ振る**という、人間にない能力を前提にしていたため、人間の打てなさを検出できなかった。

補足(トップ10に入れなかったが、人間が気づきやすい点):
- 球種の画面上の曲がり(M1 平均)は 5〜13px(ゲート1で「誇張なし」を選択済み)。球速差は D で 1310(ストレート 145)・1387(シュート)・1429(スライダー)・1462(フォーク)・1652ms(カーブ 115)だが、**最初の半分が見えない**ので速度差は最後の 400ms でしか分からない。
- 演出中に画面を触るとスキップになる。次の球でドラッグが始まらない問題(押しっぱなしの指)は H で対処済み。
- 打者のミート能力(カーソル半径)は打者ごとに違う(`meetBaseRx 0.5 + 0.004×ミート`)。

### 2.4 操作の流れ(人間が 1 球で行うこと。[コード])

1. 投手の windup(`cpuWaitMs`、約 700ms)。カーソルは中央(前の球の位置が残る)。スイングボタンは無効(灰色)。ドラッグは可能。
2. リリース(D−1310)。ボタンが有効(黄)に。HUD に「145km/h ストレート」が出る(飛行中だけ)。
3. 位置合わせ: 指を置いて**相対ドラッグ**(置いた瞬間はカーソルが動かない。1:1 のゲイン)。
4. スイング: 次のいずれか。(a) 「スイング」ボタンの押下 (b) 2 本目の指を置く (c) 1 本指なら**一度指を離し、もう一度短くタップ**(≤180ms・≤10px)。(a)(b) は押下の瞬間、(c) は離した瞬間にバットが振り始める。判定時刻は押下の時刻 − 70ms。
5. 結果: ボールが着弾点で止まる→(接触なら)打球へ。テロップは打球の落下後(約 1 秒後)。

→ 位置合わせと時刻合わせが**同時に必要**で、1 本指なら「ドラッグ(0.3〜0.5 秒)→離す→タップ」の連続動作。両手の親指(左でドラッグ・右でボタン)なら成立するが、画面にそう書いていない。

### 2.5 人間の時刻の偏りと結果(概算。[計算]。SD 70ms は[推測]。前回診断の出典の範囲)

窓: 接触 |Δt|≤150、フェア |Δt|<91.5。Δt(**遅延補正後の判定時刻** − D)が、偏り b・SD 70ms の正規分布とした場合(位置は完全に合っているとして)。

| 偏り b(ms。+ = 遅い) | 空振り(窓外) | ファウル | フェア(インプレー) |
| --- | --- | --- | --- |
| 0 | 3% | 16% | 81% |
| +60 | 10% | 24% | 66% |
| +130 | 39% | 32% | 29% |
| +200 | 76% | 18% | 6% |

(ボット D の偏りは +60ms 止まり。ボットは偏り 0 を基準にしていた。**D 基準の見た目の到達感覚が実際より +130ms 遅い人は、位置が完璧でも 4 割が空振り**。)

| **G 試遊環境の確認**(`play.html` に viewport meta を足す、またはアーティファクトの表示条件を確認) | 試遊版の包みの修正(リポジトリ外) | #10 | S | 実際に遊んだ環境の確認が先 |

暫定の見立て(推奨ではなく整理): **A1(リング)は 1 つの要素で #1(着弾点)と #2(先行合図)を同時に埋める**ので、費用対効果が見込める組み合わせの核になりうる。それに C1(離して振る)+C2(説明)+D(視認性)を足せば、「操作の仕方が分かる・ボールが追える・どこに来るか分かる・いつ振るか分かる」が揃う(パワプロの初心者向け設定に近い)。ただし A1/A3 は難易度を大きく下げるため、バランス(安打率・CPU の配球)を人間のデータで再調整する必要がある。

## 5. 未確認事項

1. **実走行・実機での観察(最優先)**: この調査では Bash が使えず未実施。次を行ってほしい(Bash が使える担当・または人間):
   - スマホ(実機)で 20 球遊び、1 球ごとに「ボールが見えた時刻」「カーソルを動かせたか」「どこで押したか」「結果」を記録する、または F のデバッグ記録を入れて回収する。
   - 仮想時計+手動 rAF の連写で、D−1310〜D+300 を 100ms ごとに撮り、ボール径・位置を画像から測って本書の計算値(2.2 章)を裏取りする。
   - 1 本指で「ドラッグ→離す→タップ」したときの実際の所要時間と、タップが無効になる率(≤180ms/≤10px を外す率)を測る。
2. **試遊環境**: どこで遊んだか(ブラウザ単体 / claude.ai アーティファクト / アプリ内)。`play.html` に viewport meta が無いこと(#10)の影響。端末・OS・フレームレート。
3. **人間の到達の知覚の偏り**: 「ボールがどこに来たら振るか」(カーソルに触れたら / 大きさ / 枠に入ったら)は人によって違うはず。実測がなく、2.5 章の表は仮定(SD 70ms)。
4. **パワプロの具体値**: カーソルの大きさ(画面比)、ボールの見える時間・大きさ、判定窓(ms)、視点、アシストの既定値の詳細は、公式ページ本文を読めておらず**未確認**。公式 URL の本文の逐語確認(`play_operation_detail01/06`、WBSC プレイガイド PDF)が要る。パワプロアプリの現行バージョンの仕様(古い攻略記事を含む)。
5. **ゲームとしての難易度の目標**: 「安打率の目標」自体を人間の目標としてどう置くか(ボット 33% は前提が違う)。攻略記事の目安「ミート打ちで 10 球中 5 球ヒット」(2022・家庭用)は参考にとどまる。
6. **ボール球/ストライクの見分け**: 人間がボール球をどれだけ振ってしまうか(振る/見逃すの判断)は、位置の予告(A1/A2)の有無で大きく変わる。
7. **球種ごとの見え方**: 本調査はストレート中央の計算が中心。変化球(D が長い、曲がりで画面上の経路が変わる)、着弾がゾーン端・外の球の時系列は未計算。
8. **UI の誤タップ**: 「ログ▴」「ホームへ戻る」「回別▾」などの小さな UI が親指の動線の近くにある。誤タップの実害は未確認。
9. **前の手のゾーン枠への掛かり**: 画像では待機中(D−400〜D+0)も手が枠の左上に掛かって見えたが、テスト報告は「待機中・投球中は重ならない」と記録している。食い違いの原因(測り方・版の違い)は未確認。
