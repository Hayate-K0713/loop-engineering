## 1. 打撃の骨格

### 1-1. 操作(v2 のタップ方式を維持し、予告・リング・ロックオン・視認性・説明・位置ずれだけを足す)

ゲート1の回答(Q1)で、パワプロ式の「触れる→スライド→離した瞬間=スイング」は**採用しない**と決まった。v2 の操作(`model/world/sequence/input-route.ts`・`arrival.ts`・`hooks/usePointerInput.ts`)を**変更せずに維持**する。以下は現行コードを読んで確認した動作で、v3 でも同じである(「ステージ」= 入力面 `bb-stage__input`)。

| 入力 | 動作(v2 のまま) |
| --- | --- |
| タッチ pointerdown(演出中 = `holding`) | `routeStagePointer` が `skip`。演出をスキップし、この指は「持ち越しの指(held)」になる |
| タッチ pointerdown(1 本目の指 = `isPrimary`、`enabled`) | `drag-start`。**カーソルは動かさない**(相対ドラッグの起点を覚える)。`swingReady` が真なら**タップ候補**を記録し、到達通知(`PITCH_ARRIVED`)を最長 `TAP_ARRIVAL_HOLD_MS`(200ms)保留する |
| タッチ pointerdown(2 本目以降の指) | `swing-here`。現在のカーソル位置で**即スイング**(押した時刻。`swingReady` でなければ何もしない) |
| タッチ pointermove(ドラッグ中) | 指の移動量だけカーソルが動く(1:1)。押下位置から 10px を超えたらタップ候補を取り消し、保留を解く |
| タッチ pointermove(スキップに使った指の、演出後の最初の move) | `drag-start`(その指が相対ドラッグを始める) |
| **タッチ pointerup** | タップ候補で、**持続 ≤ 180ms かつ移動 ≤ 10px**(2 つのイベントの `timeStamp` の差。`isTapGesture`)なら、**押下時点のカーソル位置・押下の時刻**でスイング(`swingAtMs` の `origin.timeStamp` = 押下)。スイングを先に出し、そのあとで保留を解く。それ以外(ドラッグした・長押し・スキップに使った指)は何もしない |
| マウス/ペン | move でカーソルが絶対位置に追従。主ボタンの押下で、その位置で即スイング |
| スイングボタン | 押した時刻で即スイング(両手持ち用の補助。ボタンの種別: ミート/強振) |
| キー(矢印/WASD、Space/Enter、Z/X) | v2 のまま(`defaultPrevented` の排他。[[dom-key-input-exclusivity]]) |
| pointercancel | スイングしない。タップ候補を捨て、保留を解く |

- **判定時刻**: `atMs = (押下の timeStamp − リリース時刻)×timeScale − 70ms`(遅延補正。v2 §2)。タップのスイングは**押下の時刻**で判定する(離した時刻ではない)ので、指を離すまでの最大 180ms は判定に含まれない。
- **見逃し確定 D+250ms(v2)**と到達通知の保留(≤ 200ms)は変更しない。タップ候補の指が下りている間だけ保留し、離す・取り消し・unmount で解く。押下が到達の前なら、離しが D+250 を過ぎても押下の時刻で判定される(遅い +xxx ms の空振りになりうる)。押下が到達の後(`swingReady` が偽)のタップは無視される(空振りにならない)。
- **守備中のステージもスクロール・長押しを無効にする**: `.bb-stage__input--active`(`touch-action: none`)は人間打撃中だけでなく**人間守備中も付ける**。`-webkit-touch-callout: none`・`-webkit-user-select: none` を付け、ステージの `contextmenu` を `preventDefault` する。Playwright の touch エミュレーションでは再現できないので、**試遊ログに pointercancel の回数と時刻・押したのにスイングにならなかった理由を記録**する。

#### タップ方式でも残る穴の整理(ラウンド1・2のレビューの再整理)

レビューで挙がった v2 由来の問題のうち、離す=スイングに固有だったもの(M1 の D+250 のイベント時刻による打ち切りと保留の延長、持ち替えガード D−300、持ち越しの指の昇格、`expired`、`takeRelease`/`regripRate`)は**不要になったので削除した**。タップ方式でも起きるものは次のとおり整理した:

| # | 穴 | タップ方式での扱い |
| --- | --- | --- |
| T1 | **押したのにスイングにならない**(長押し 180ms 超、10px 超の移動)が黙って無効になる | **直す**: 純関数 `tapReleaseReason`(A4)が `tap-too-long`/`tap-moved`/`not-ready`/`holding`/`cancel`/`held-release` を返し、**短いヒント**(「タップは すばやく ポンと おす」、最大 3 回)を出し、試遊ログに理由を記録する。判定の閾値(180ms/10px)は変えない |
| T2 | **スキップに使った指はスイングできない**(その指は離しても振れず、最初の move でドラッグを始める) | **仕様として維持**: 離してもう一度タップする、2 本目の指・スイングボタンで振る。離す=スイングを採らないので、昇格の規則は作らない。`held-release` を試遊ログで数え、多ければ T1 の結果でヒントを足す |
| T3 | **見逃し後のタップ**: 到達の後に押したタップは `swingReady` が偽で**無視**される(空振りにならない)。到達の前に押して離しが後になったタップは、押下の時刻で判定される(遅い +xxx ms の空振り)。この境界を単体テストで固定する | **確認のみ**(コードは不変。A4 の境界テスト) |
| T4 | **ロックオンの時刻**: タップは離したときにスイングが出るが、有効カーソル(ロックオン後)の計算は**押下時刻の進行度 `progress`**で行う。離した時刻で計算すると、押下時に表示されていたカーソルと判定に使うカーソルが食い違う | **直す**: `onSwing(origin, cursorAtDown)` が受け取る素のカーソル `cursorAtDown` に、押下時刻の `progress` で `lockOnCursor` を適用して `SwingInput.cursor` と `assistK` を作る(A9。受け入れ C5 に追加) |
| T5 | **3 動作の重さ**(ドラッグで合わせる → 離す → タップ)がそのまま残る(v2 の不満の一因) | **緩和のみ**(ユーザーが方式を選択済み): ロックオンで合わせの精度を補い、チュートリアル・ヒントで「合わせたら、もう 1 本の指かスイングボタンで振る」を勧め、スイングボタン(80px)を常に押せる。T1 のログ(使われた入力種別)で見直す |
| T6 | **到達の保留(≤ 200ms)と処理遅延**: 描画が遅れてタップの離しの処理が 200ms を超えて遅れると、到達通知が先に出て見逃し扱いになる(保留の期限は壁時計) | **維持**(v2 の挙動)。`fps` の p95 が悪い端末ではティアが下がる。ログの `held-release`/`not-ready` と fps で切り分ける |

### 1-2. 着弾点の予告(`preview`)と縮むリング(先行合図)

投球がリリースされた瞬間(`flight` の出現。t = 0)から、**着弾点に予告の印**を出し、その周りに**D に向かって縮むリング**を出す。リリース前(windup 中)は着弾点が決まっていないので出さない(`CPU_PITCH` の dispatch がリリース時のため。残り約 1.3 秒ある)。

- **リング**: 着弾点(ゾーン平面)を中心に、半径が t = 0 で `startRadius`(0.30m。390 幅で約 89px)、t = D で `endRadius = ballRadius × 1.25 = 0.125m`(約 37px。ボールの縁のすぐ外)になる**線形**の縮小(D 以降は D の半径で保持)。**ボールが着弾点に着いた瞬間にリングがボールを囲む**。これが「先行する今の合図」(v2 のゾーン枠の発光は D−20ms からの結果の合図で、反応時間 200ms 超の人間には使えなかった)。ゾーン枠の発光は残す。線幅は画面で約 3px(「画面上の px の扱い」)。
- **点の見せ方は難易度で変える**(アシストの `preview`): `exact` = 着弾点の真上に小さな点(半径 0.04m・シアン・黒縁)。`fade` = フェードカーソル(点は出さず、半径 `fadeRadius` の薄い円を、着弾点から `seq` から決まる決定論のずれ `fadeJitter` 以内で動かした位置に出す。円は必ず真の着弾点を含む)。`none` = 点も円も出さない(リングは出る。ボットの v2 設定とロールバック用)。**色はシアン(0x5ce1ff)**にして、黄色のカーソルと区別する。
- **変化球**: 予告は**最終の着弾点**(`flight.landing`)に出す。軌道の曲がりは従来どおり(誇張なし)。
- **ボール球かストライクかは、予告の点がゾーン枠の内か外かで分かる**(ふつうまで)。
- 出現は 120ms でフェードイン(`fadeInMs`)。D + `hold`(接触なしは消失時刻)まで残す。

### 1-3. ロックオン(カーソルの補正)とアシストの強さ

ロックオン = 指で動かした「素のカーソル」(`raw`)を、飛行中に着弾点へ**部分的に引き寄せた「有効カーソル」**を判定と表示の両方に使う(表示と判定は常に同じ有効カーソル。**タップのスイングでは押下時刻の有効カーソル**。§1-1 の T4)。

```
progress p = clamp(t / D, 0, 1)
dist       = ゾーン単位での raw と landing の距離(ユークリッド)
capture    = 1 − smoothstep(captureRadius, captureRadius × 1.6, dist)   // 遠すぎるボールは引き寄せない
ramp       = smoothstep(rampStart, rampEnd, p)                          // 早い時刻は素のカーソル、終盤で効く
k          = lockStrength × capture × ramp
effective  = raw + (landing − raw) × k
```

- 判定に使うカーソルは `effective`(`SwingInput.cursor`)。`SwingInput.assistK = k` も渡す。**質 q は `k` が大きいほど下げる**: `q' = q × (1 − qualityPenalty × k)`(補助なしの上手い人のほうが強い打球を打てる)。
- 難易度ごとの出発値(`ASSIST_TABLE`。A14 がボットで調整してよい):

| 難易度 | lockStrength | captureRadius(ゾーン単位) | rampStart / rampEnd | preview | fadeRadius / fadeJitter | qualityPenalty |
| --- | --- | --- | --- | --- | --- | --- |
| かんたん | 0.80 | 1.6 | 0.30 / 0.80 | exact | — | 0.30 |
| **ふつう(既定)** | **0.55** | **1.2** | 0.35 / 0.85 | exact | — | 0.35 |
| むずかしい | 0.20 | 0.7 | 0.40 / 0.90 | fade | 0.45 / 0.25 | 0.40 |

- アシストは**難易度に連動**する(新しい設定 UI は作らない)。「むずかしい」も縮むリングと視認性の改善は入る。**タップ方式ではカーソルを合わせる 3 動作の重さが残る(§1-1 T5)ので、ロックオンの効きは離す=スイング案より重要になる**。T1 のログで強度を見直す。

### 1-4. ボールの視認性と「画面上の px の扱い」

モック(M2・M3)で、**最小径にしても白い投手の服の前では輪郭が弱い**ことが分かった。ハローを必須にし、縫い目は「見える距離」を現実的に定めた。

| 項目 | v2 | v3 |
| --- | --- | --- |
| 飛行中の最小表示径 | 無し(リリース 7.5px) | **飛行中も最小表示径**: `ballScaleFor(camera, ball, minRatio)` に飛行用の `minScreenDiameterRatioFlight = 0.0175`(390×844 で約 14.8px)。リリース直後は約 2.0 倍、**D−730ms 付近**で 1 倍に戻る(連続・単調) |
| 縁取り | 球の 1.12 倍の黒い殻 | 殻の太さを**画面で 2px 以上**に保つ(`outlineScaleFor`。`ball.outlineScale`) |
| 白い服との重なり | 重なる | **ハロー(必須)**: 球の 1.9 倍の暖色(#ffd9a0)の半透明円(不透明度 0.35)を球の後ろに敷く。ハローは常に表示し、輪郭と合わせて背景によらず見える。モックで「不十分」なら `halo.opacity` を 0.5 まで上げる(D3 が調整)。**夜(最大)ではハローと縁取りの視認性を再確認する** |
| 縫い目・回転 | 無し | **太い赤い帯(球の径の 18% 幅の弧 2 本)**と**回転**。**径 15px 前後(飛行の前半)では帯の回転がかろうじて分かる程度で、縫い目の形が見えるのは D 付近(径 30px 以上)**。前半の手がかりは最小径・ハロー・予告のリングとし、球種の見分けは D−700ms 以降の回転と球種チップ・球速で行う |
| 位置の手がかり | 影(円盤1つ) | 影は残す。予告の点とリングが主役 |

**画面上の px の扱い**: 「画面で 2px 以上」「線幅 3px」は、px ではなく**画面高さに対する比**(`shellMinRatio = 0.0024`・`ringWidthRatio = 0.0036`。844px で 2px・3px)で `WORLD_PARAMS` に置き、`model/world/camera/rig.ts` の `outlineScaleFor`・`ringWidthFor(camera, point, widthRatio)` が `ratio × 2 × dist × tan(fov/2)` で m に換算して `SceneFrame.ball.outlineScale`・`SceneFrame.guide.ring.width`(m)に入れる。render は受け取った値をそのまま使う。

### 1-5. 説明(チュートリアル)

- **初回の表示**: 初めて人間が打つ(または投げる)ときに、1球目を始める前に**カード**(3 ページ。「つぎへ/はじめる」ボタン 44px 以上)を出す。**表示中は専用のフラグ `tutorialActive` で次の投球を始めない**(`holding` には合成しない。`tutorialActive` 中はステージの入力を `enabled = false` にし、`useCpuTurn`・人間の投球開始はこのフラグも見る)。既読は `localStorage`(`bb-tutorial-v1`。使えない環境ではメモリのみ)。HUD の「?」でいつでも再表示(`idle` のときだけ)。
- **打撃のカード(タップ方式)**: ①「ゆびを のせて スライドすると カーソル(きいろ)が うごく」②「ボールが くる ところに ● が でる。カーソルを ● に あわせる」③「リングが ● に かさなる しゅんかんに **タップ!** (もう 1 ほんの ゆび か ボタン でも OK。ゆびを うごかさず ポンと おす)」。**投球のカード**: ①「球しゅを えらぶ」②「ゾーンを なぞって ねらいを きめて ゆびを はなす」③「リングが ちぢんで ねらいに かさなる しゅんかんに タップ!(ぴったりで ナイスピッチ)」。(「見逃すときは指を離さず待つ」は離す=スイングを採らないので入れない。)
- **最初の数球のヒント**: 人間の打撃・投球のそれぞれ最初の 5 球は、画面下に 1 行のヒント。タップが通らなかったときは §1-1 の T1 のヒント(「ポンと おす」)。
- 画面の絵(指のアニメーション)は CSS だけで描く(画像なし)。

### 1-6. スイング後の位置ずれ表示と、接触後のカメラ(ラウンド2 R2-M1 で全面改訂)

**旧案の誤り**: ラウンド1の案は「接触後もカメラを打撃位置に `chaseDelayMs = 300ms` 残し、その間に 3D の十字と輪を見せる」とし、「打球は打撃カメラから遠ざかって見える」としていた。`play-plan.ts` の `chaseFromMs = contactMs`(v2)に 300ms を足す案だが、打撃カメラ(C = (0, 1.75, 2.6)、lift 0.219)で検算すると、**ホームラン(115m・頂点 27.6m・滞空 4220ms)は接触の 150ms 後に画面 y ≈ −172px、300ms 後に y ≈ −379px と画面の上に消え、ライナー(60m・頂点 4.8m)は 300ms 後に y ≈ 66px で HUD(155px)の下に隠れる**。画面に残るのはゴロだけである。「接触から落下まで打球が縦に画面内」を守る `rig.test.ts` の既存のテストとも矛盾する。

**3 案の比較と決定**:

| 案 | 内容 | 長所 | 短所 | 判断 |
| --- | --- | --- | --- | --- |
| (a) 遅延をゴロ性の当たりに限る | 接触後 300ms の遅延を、ゴロ性の当たりと空振り・ファウルにだけ入れる | 3D の表示をそのまま使える | フライ・ライナー・HR では位置ずれが見えない(一貫しない)。ゴロでも打球が遠ざかる。分岐が増える。テンポ +300ms | 採らない |
| (b) 遅延の間も注視点を打球へ blend し始め、位置だけ残す | 追跡カメラの位置は打撃位置のまま、注視点だけ打球へ寄せる | 打球が画面に残る | 注視点の移動でゾーンも画面から外れる(3D のマーカーがずれる)。`rig.test` の blend の前提が変わる | 採らない |
| **(c) 3D をやめ、ゾーン矩形に追従する DOM(十字と輪)にする** | 位置ずれ(判定に使った有効カーソルと、ボールの着弾点)を、`zoneRect`(打撃カメラのゾーン矩形)に固定した DOM のミニ図で出す。カメラは v2 のまま(`chaseFromMs = contactMs`) | **遅延が不要**(テンポ +0)。カメラの動きと無関係に 900ms 見える。ピルと同じ仕組みで新しい仕組みが少ない。`rig.test` の既存のテストが不変 | DOM の図は追跡カメラの画面に重なる(ボールが重なる可能性) | **採用** |

**決定(c)**:

- 接触・空振り・ファウルなど、スイングした全結果で、`ui/ZoneFeedback.tsx`(DOM)が `zoneRect` の位置に**ミニ図**を出す: 薄いゾーン枠(`frameAlpha 0.35`・線のみ)、**白の十字(判定に使った有効カーソル。径 16px)**、**シアンの輪(ボールの着弾点。径 30px)**、2 点を結ぶ線(線幅 3px)。ゾーン単位 → px は `zoneRect` で換算する(純関数 `zoneFeedbackOfSwing` が `ZoneFeedbackView`(ゾーン単位)を返し、UI が px にする)。**塗りつぶさず線だけ**にするので、追跡カメラに切り替わったあとも背後の打球が見える。
- 表示は `zoneFeedback.swingMs = 900ms`(フェードアウト)。`pointer-events: none`。スキップ(タップ)で即消える。
- 守備(`tone: "pitch"`)の「狙いと着弾の重ね表示」も同じ `ZoneFeedback`(`zoneFeedback.pitchMs = 700ms`)で出す。
- **3D の `SceneFrame.feedback` は作らない**(型・render・`frame.ts` の合成から外す)。タイミングのピル(2 行)は v2 のとおり DOM。
- **`chaseDelayMs` は無い**。`PlayPlan.chaseFromMs = contactMs`(v2 のまま)。1球のテンポの +300ms も無い。
- **リスク**: 追跡カメラの画面でミニ図がボールに重なって見える可能性。線だけ・半透明にして緩和し、D3 の連写で「ホームラン・ライナー・ゴロ」の 3 種で確認する。重なりが問題なら、ミニ図を接触後 300ms だけ濃く、その後は薄くする。

## 2. 投球の骨格(案 C の簡略版: ゾーン直接ドラッグ+リングゲージ)

**守備の操作(ゾーンをなぞって狙い、離して確定、ゲージ)はゲート1の回答でも変更なし**(守備は「離して確定」だが、打撃の操作方式とは別である)。

**選択肢(調査 pitching.md)と選択**

| 案 | 内容 | 腕前の要素 | パワプロらしさ | 工数 | v3 の判断 |
| --- | --- | --- | --- | --- | --- |
| A 現行改善 | 格子は残し windup 短縮・重ね表示・σ 調整 | 無し | 低 | S〜M | 採らない(腕前が戻らない) |
| B ゲージ追加 | 格子+ゲージ | ゲージ | 中 | M〜L | 採らない(格子は遠く間接的) |
| **C ゾーン直接ドラッグ+ゲージ** | ゾーンをなぞって狙い、離して確定、ゲージをタップで止める | **位置+ゲージ** | **高** | L | **採用(簡略版)** |
| D ワンジェスチャ | 押したまま動かして離して投げる | 位置のみ | 中 | M〜L | 採らない(誤タップ・腕前が弱い) |

**採用理由**: (1) 打撃の操作(ゾーンを相対ドラッグ+縮むリング)と近い言語になり、1つのチュートリアルで済む。(2) 腕前が2要素(位置の精度・タイミング)で結果に効く。(3) ゾーンが大きく見える構図にでき、格子を操作バーから外すので画面が空く。

**流れ(人間守備)**

```
[球種チップを選ぶ] (常時。球速と曲がり矢印つき)
        ↓
(idle) ステージに指を置く → (aiming) 狙いの照準が出る。スライドで動く(相対ドラッグ、散布円で「ブレの目安」を表示)
        ↓ 指を離す(= 狙いを確定)
(gauge) 照準の周りのリングが 900ms かけて縮む(戻らない。終点を過ぎても 300ms は縮み続ける)
        ↓ リングが照準に重なる瞬間にタップ(ステージのどこでも / 「とめる!」ボタン / Space)
(throwing) 質が決まる(ナイス / グッド / ふつう / 失投) → windup 280ms → 投球 → 飛行 → 着弾
        ↓
着弾から 700ms: 狙い(白の十字)と着弾(シアンの輪)を DOM のミニ図(ZoneFeedback)で重ねて表示 + 「ナイスピッチ!」「ズレ 0.2」等
```

- **守備側の持ち越しの指(スキップに使った指)**: 演出中にスキップに使った指(held)は、**離してもゲージは始まらず、狙いの確定にもならない**(`aiming` に入っていないので、離しは `none`)。その指は**最初の pointermove で狙いの指(aiming)になり**、以後は通常の規則(離すと狙いを確定)。持ち越しの指が複数あるときは、最初に下りた `pointerId` を昇格する。ゲージ中の押し(停止)は、ゲージ開始後の pointerdown だけを数える。B1 の状態機械・B4 の hooks に実装する。(打撃のタップ方式とは独立の、守備の「離して確定」のための規則。)
- **質の決まり方**: ゲージの誤差 `e = (停止時刻 − 入力種別の遅延補正) − (ゲージ開始 + 900ms)`。遅延補正は入力の種類別(タッチ 70ms・マウス/キー 20ms)。`|e| ≤ 40ms` = ナイス、`≤ 90ms` = グッド、`≤ 160ms` = ふつう、それ以外・タップなし(自動投球)= 失投。**ゲージ開始から `stopGuardMs`(250ms)は停止を受け付けない**(ダブルクリックが失投になるのを防ぐ)。
- **着弾のばらつき**: v2 の σ(`baseSigma 0.28 × 制球 × 疲労`、人間の制球 63 で約 0.384)に質の倍率を掛ける: ナイス ×0.35 / グッド ×0.65 / ふつう ×1.0 / 失投 ×1.7 かつ**狙いを真ん中やや高め(0, 0.15)へ 60% 引き寄せる**。乱数の消費数は変えない(ガウス 2 回のまま)。
- **質ごとの「狙いと着弾のずれ」の見え方**: 平均のずれ(σ√(π/2)、ゾーン単位 → 390×844 で 1 単位 ≈ 77px)は、ナイス ≈ 0.17(≈ 13px。照準と点がほぼ重なる)、グッド ≈ 0.32(≈ 25px。点が照準の輪の縁)、ふつう ≈ 0.48(≈ 37px。輪の外)、失投 ≈ 0.8 + 真ん中への引き寄せ(≈ 65px 以上。大きく外れて「甘い」)。重ね表示の点と線は、ナイスでも見えるよう**照準の輪を細く(外周 44px・線幅 2px)、着弾の点を径 24px のシアン**にし、距離のラベル(「ズレ 0.2」)を添える。M10 のモックは**ナイスのケースだけ**なので、ふつう・失投の絵を追加で作る(ゲート1の資料)。
- **狙いは連続座標**(ゾーン単位。±1.67 に制限)。`PitchCommand` を `{ kind, aim: ZonePoint, quality }` に変え、CPU は `CpuPitchChoice { kind, cell }` を返し、reducer がセル中心を `aim` に直して `quality: "normal"` で投げる。
- **PC・キー**: マウスは動かすと狙いが追従、クリックで確定、もう一度クリック(または Space)で停止。キーは矢印で狙いを動かし、Space/Enter で確定→停止。「投げる」ボタン(`throw-pitch`)は、`idle`/`aiming` では「確定」、`gauge` では「とめる!」を同じ操作として受ける。
- **入力面の受け持ち**: 守備中の `bb-stage__input` のポインタイベントは `usePitchingControls` が受け、打撃中は `usePointerInput` が受ける(`useGameStage` が人間打撃/守備のモードで選ぶ)。**演出中のスキップは守備でも `routeStagePointer`(`holding` なら `skip`)を先に通す**。`usePitchingControls` は座標変換のため `pickZone`・`getZoneRect` を注入で受ける(自分では `getBoundingClientRect` を使わない)。
- **球種チップ**: 球種名・球速・曲がり矢印。1つ 76×52px。常に選べる。

**CPU 打者との整合**

- `PitchFlight.quality` と着弾位置の「縁度」(`extent = max(|x|, |y|)`)で、CPU 打者の入力ノイズを変える。`cursorSigma × qualityFactor × locationFactor`、`timingSigmaMs × (qualityFactor^0.5) × locationFactor'`。`qualityFactor` = ナイス 1.7 / グッド 1.25 / ふつう 1.0 / 失投 0.65(難易度の `qualitySensitivity` で冪にする: かんたん 1.2 / ふつう 1.0 / むずかしい 0.6)。`locationFactor = 1 + 0.9 × max(0, extent − 0.5)`、`locationFactor' = 1 + 0.4 × max(0, extent − 0.5)`。失投は振る確率も ×1.25(上限あり)。
- **同じ球種の連投は不利**にする: 直前の球種が同じなら `cursorSigma` を ×0.85。
- CPU 同士(`balance.test.ts`)も位置・質に反応するので打率が下がる。B3 が出発値を調整し、**`balance.test.ts` の基準は変えない**。

**テンポ**: 人間の windup 700ms → **280ms**、CPU の windup 700ms → **550ms**、テロップ: ボール 500 → 380ms、空振り 700 → 520ms、ファウル 700 → 520ms、インプレー 1100 → 900ms、余韻 200 → 120ms。**1球の所要(スキップなし)の式**: `windup + D + (人間打者で指が無い見逃し: lateCutoffMs / CPU 打者: 前倒し分を引いて 0)+ テロップ + 余韻`。ストレート(D = 1310ms)の CPU 投手・人間打者の見逃しで 550 + 1310 + 250 + 380 + 120 ≈ **2.6 秒**(v2 は約 3.0 秒)、カーブ(D = 1652ms)は +342ms。**タップ候補の指が下りたままの見逃しは最大 +200ms(到達通知の保留 `TAP_ARRIVAL_HOLD_MS`)**。**走者が動くヒットは +最大 3.0 秒(走者の進塁。スキップ可。最大のスライディングを含む)**。接触後のカメラ遅延は無い。人間の投球は(狙い 約 0.5 秒+ゲージ 約 1.0 秒+windup 0.28+飛行 1.33+結果 0.5)で約 3.6 秒。

### 3-2. 演出(バナー・接触演出・位置ずれ)

- **バナー(`ui/EffectBanner`、DOM+CSS)**: 純関数 `bannerFor(outcome, landing, timing)` が文言・種類・色・表示区間を決める。種類: `just`、`hit`、`homerun`(全面フラッシュ+大文字+紙吹雪の CSS)、`strikeout`、`walk`、`out`、`nice-pitch`。**位置**: 画面上から **y 312〜408px(37〜48%)** の斜めの帯(投手の足元 y ≈ 270 とゾーン上端 y ≈ 433 の間の空き)。投手の頭・HUD(y < 170)には掛けない。ホームランの全面フラッシュは意図的に HUD にも掛けるが、**大文字(「ホームラン!!」)はこの帯の中**に収める(最大高さ 120px)。ボール/ストライク/空振り/ファウルは v2 のテロップのまま。バナーが出る結果はテロップを出さない。スキップ(タップ)で即消える。
- **接触演出(純関数 `hitFxAt`)**: ジャスト・強い当たりで**ヒットストップ**(60ms〜40ms)、**ズームパンチ**(接触後 140ms で FOV を 4% 狭めて戻す)、**微小なシェイク**(振幅 0.012m)。`prefers-reduced-motion` では全て無効。
- **位置ずれ表示**: §1-6 のとおり(DOM のミニ図 `ZoneFeedback`)。タイミングのピルは 2 行(1 行目 = 「ジャスト!」「早い −62ms」「遅い +48ms」、2 行目 = 「芯」「ふつう」「かすり」「ミス」)。

### 3-3. 音と触覚

- **音(Web Audio の合成。`audio/` + `model/sound/`)**: 外部素材なし。効果音一覧(`SfxCue`): `pitch-release`、`mitt`、`swing-miss`、`hit-just`、`hit-normal`、`hit-weak`、`foul`、`grounder`、`homerun`、`cheer-small`・`cheer-big`、`strike`・`ball`・`out`・`strikeout`・`walk`、`ui-tap`・`ui-select`、`gauge-tick`、`nice-pitch`、`throw`(送球)・`catch`(捕球)。**最大の追加(段階 M の M12)**: `slide`(滑り込み)、`crowd-swell`(観客のどよめき)、`replay-start`。音色は「レシピ」(型 `SfxRecipe`)で定義し、純関数 `sfxEventsOf(plan, flight)` が「いつ・どの音を」を決める。`audio/engine.ts` は **`createAudioEngine({ recipes, createContext })`**。
- **iOS・autoplay**: `unlock()` は**ユーザー操作として認められるイベント**(`pointerup`/`touchend`/`click`/`keydown`。`pointerdown` では解除されない)の中で行う。`suspended`/`interrupted` からの復帰は `visibilitychange` と次の操作で `resume()`。
- **既定は ON**(ゲート1で決定。最初の操作の後)。HUD のスピーカーボタンと、タイトルの切替(`bb-prefs-v1`。保存は任意)。iOS のマナーモードでは鳴らないのでチュートリアルに一言。音のデモ: [公開 URL](https://claude.ai/artifact/MSGWqALkJJRty6nptyeiAP)(リポジトリ内 [sfx-demo.html](assets/2026-10-27-baseball-game-v3/sfx-demo.html))。
- **触覚(`navigator.vibrate`。Android のみ。既定 ON)**: 最短 15〜20ms(スイング 15ms、ジャスト 25ms+短い間+35ms、ヒット 20ms、ホームラン [30,40,30,40,90]、三振 30ms、ナイスピッチ 20ms)。80ms 未満の連続は間引く。`prefers-reduced-motion`・設定 OFF で無効。
