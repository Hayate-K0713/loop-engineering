## 要旨(先に読む)

- **何を直すか**: v2 修正版は自動テスト全合格・ボット安打率 33%・コードレビュー PASS で通ったが、ユーザーがスマホで遊ぶと「打てない」「投げるのもカス」「パワプロに程遠い」と不合格になった。さらにゲート1用のモックを見たユーザーが「パワプロじゃねーだろうが全然」と言い、**キャラクターの見た目(顔・表情・頭身・ユニフォーム・動き)が最大の不満の一つ**と分かった。調査の結論は、(1) 打撃は**着弾点が事前に分からず、振る合図が無く、操作の説明も無い**、(2) 投球は**人間の腕前が結果に効かない**、(3) 画面は**打者の後頭部が画面の半分を占め、キャラクターは顔も表情も個性も無い同一人形で、音が一切ない**、(4) **検証が人間の代理になっていなかった**。
- **ゲート1の回答(2026-10-30)で決まったこと**: (1) キャラクターの作り込みは**「最大」**(標準 + スライディング・ベースカバー・選手別の固有フォーム・観客の動き・球場の作り込み・リプレイ)。(2) 打撃の操作は**「タップでスイングのまま」**(v2 の操作を維持。離す=スイングは採用しない)。(3) 音と振動は既定 ON。(4) 中間試遊(T1・T1b)を入れる。
- **v3 の基本線**: 打撃の骨格(着弾点の予告・縮むリング・ロックオン・ボールの視認性・初回の説明・位置ずれ表示。**操作は v2 のタップ方式のまま**)、投球の骨格(ゾーンを直接なぞって狙い、縮むリングにタップを合わせるゲージで質が決まる)、**キャラクターの作り直し(顔・8 種の表情・髪型・ヘルメット/帽子・背番号・20 人の個性・肘と膝のあるフォーム・走者の3D化・捕球と送球・顔アップのワイプ。外部素材なし、three の `SkinnedMesh`+コード生成テクスチャ)**、**最大(スライディング・ベースカバー・20 人の固有フォーム・観客の動き・球場の作り込み・時間帯・スコアボード・リプレイ・イントロ)**、見た目・手応え(打者を小さく端へ・カットイン/バナー・Web Audio の合成効果音・振動)、検証の作り直し(人間代理ボット v2・投球ボット・実機の試遊ログ)。
- **覆す v2 の決定**: 「サウンドはやらない」、「初心者アシストはやらない」、「守備側の操作改善はやらない」、「縦長カメラ x −0.25(Q-B)」、「キャラクターは同一モデル・顔なし」「走者の3D表示・送球はやらない」。**維持**: **タップでスイング(Q-A。ゲート1で維持と決定)**、外部素材禁止、three addons 不使用、チームごとの色、タップでの演出スキップ、演出の後に更新、ホーム画面のレイアウト、見逃し確定 D+250ms、到達通知の保留(≤ 200ms)。
- **実装は 6 段階(A 打撃の骨格 → E キャラクター(標準)→ B 投球の骨格 → C 演出・音 → M 最大 → D 検証・調整)**で、**57 ステップ**(最大の追加分 = **段階 M の 14 ステップ・4 ウェーブ**)。各段階の終わりに全体が緑になる。**A の完了時点で打撃だけが遊べるビルドを人間に渡し(T1)、E の完了時点でキャラクターの見た目を人間に確認してもらう(T1b)。M の完了後は任意で T1c**。ゲート2の前に、ボット以外の「人間が実機で遊ぶ」確認を必ず入れる。
- **描画負荷の設計**: キャラクターは `SkinnedMesh` + 共有 `Skeleton` で 1 体を 4 draw call(遠景は 2)にし、キャラクター全体で約 41(目標 ≤ 60)。最大の追加(観客・看板・照明塔・スコアボード・土煙)は T0 で +約 10 draw call・+約 21k 三角形。実機 fps が足りないときは、自動で品質を 4 段階に落とす(切替は飛行中を避ける。重い場合は 2 段降格。観客の体数・リプレイ・イントロなども縮む)。
- **構図と球場の関係(最大の設計の前提)**: 打撃・守備のカメラでは、観客席の上段・スコアボード・照明塔・ダグアウトは HUD の裏か画面外で**映らない**(映るのはフェンスと観客席の下段の約 50px の帯と、芝)。球場の作り込みの主役は**追跡カメラ(HR でスタンド)・内野カメラ・リプレイ・イントロ**で見せる設計にした(max 分冊 §3-5-1 の検算)。

## 目的・スコープ

### 目的

スマホで遊んで、**打てる・投げられる・パワプロっぽい手応えと見た目がある**ブラウザ野球にする。自動テストの数値(特に v2 のボット)を人間の根拠にせず、「人間が遊んで楽しいか・見て『それっぽい』か」を受け入れ基準の中心にする。

### v2 で何が起きたか(前回の失敗と再発防止)

| 前回の失敗 | 原因 | v3 での再発防止(本書の該当箇所) |
| --- | --- | --- |
| 打率 33% のボットが合格だったのに人間は「打てない」 | ボットが (a) ストライクだけ振る (b) 到達時刻を偏りなく知覚する (c) 着弾点を 3D の直線外挿で完全に推定する (d) 指の移動・持ち替え時間が無い (e) 個人差が無い(調査 batting.md 2.6) | 「検証 — 人間代理ボット v2」: 見分け誤り・知覚の偏り・2D からの推定誤差・Fitts の法則・**個人差の分布(P10/P50/P90)**・**タップ方式で生じる失敗の型**を入れ、**v2 設定で「打てない」を再現できること(検出力テスト。調整先は共有パラメータに限る)**と**悲観シナリオ**を受け入れ基準にする |
| 守備側(投球)は腕前が結果に効かないまま、検証も無かった | 投球の結果は狙いセル中心にガウス誤差を足すだけ(pitching.md) | 投球の腕前(狙いの精度+ゲージ)を結果に効かせ、**投球ボット**で「上手い人ほど抑えられる」を数値で守る |
| 見た目・音が「やらないこと」に落ちたままゲート1を通った(`visual-scope-must-be-shown-at-gate1` の再発) | サウンド・カットイン・構図・キャラクターの作り込みを「スコープ外」にして承認を得た | gate1 分冊に、**実描画のモック(構図の数値つき)・操作の流れ図・音のデモ・ロックオン強度の表・キャラクター/最大のモックの作り方**を列挙した。**度合いと打撃中の打者の顔はユーザーが選択済み(最大)** |
| 実機で遊ぶまで不満が見えなかった | 実機の入力・体感のデータが無い | 「実機の試遊ログ」(端末内に記録、**localStorage に依存せず画面から取り出せる**)と「遊べる版を人間に渡すタイミング(T1・T1b・T1c・T2)」を設計に入れる |

### やること(P0)

1. **打撃の骨格(タップ方式のまま)**: ①着弾点の予告(`exact`/`fade`)②縮むリング(到達の先行合図。枠の発光は結果の合図として残す)③ロックオン(難易度で強さを変える。ふつうは初心者が打てる既定。**タップ時刻の有効カーソルで判定**)④ボールの視認性(最小径・縁取り・ハロー・縫い目と回転)⑤初回のチュートリアル表示と、最初の数球の画面内ヒント⑥位置ずれ表示(DOM)⑦**タップが通らなかった理由の記録とヒント**。操作(1 本指のドラッグ+タップ、2 本目の指、スイングボタン、キー、マウス)は v2 のまま。
2. **投球の骨格**: 調査の案 C(ゾーン直接ドラッグ+ゲージ)の簡略版を採る(play 分冊 §2)。狙い→ゲージ(縮むリングをタップで止める)→質(ナイス/グッド/ふつう/失投)が着弾のばらつきを決める。狙いと着弾の重ね表示、windup の短縮、1球のテンポ短縮、CPU 打者の反応(位置・質)。**守備の操作はゲート1の回答でも変更なし**。
3. **キャラクターの作り直し(標準。character 分冊)**: 2〜2.5 頭身のデフォルメを保ったまま、顔・8 種の表情・髪型・ヘルメット/帽子・肌色・体格・ユニフォームの質感と背番号・選手ごとの個性・肘と膝のあるフォーム・走者の3D化と進塁・野手の捕球と送球・顔アップのワイプ。**外部素材なし**。描画予算(`SkinnedMesh` 方式)と品質の自動切替。
4. **最大(max 分冊。ゲート1の回答)**: スライディング・ベースカバー、20 人の選手別の固有フォーム、観客の動き(インスタンス描画)、球場の作り込み(看板・照明塔・芝の模様・ダグアウト・スコアボード)、時間帯の照明(昼/夕/夜)、リプレイ(3 カメラ・スロー。`sceneFrameAt` の純粋性を活かす)、試合開始のイントロ。最大の描画予算を品質ティアに組み込み、足りないときは自動で落とす。
5. **見た目・手応え**: 打撃・守備の構図(打者を小さく端へ、守備はゾーンを大きく、投手を大きく)、カットイン/バナー演出、接触演出(ヒットストップ・カメラの食いつき)、位置ずれ表示(DOM のミニ図)、Web Audio の**合成効果音**(外部素材なし。**既定 ON**)、振動(Android のみ。既定 ON)、音・振動のミュート設定。
6. **検証の作り直し**: 人間代理ボット v2、投球ボット、検出力テスト、**実機の試遊ログ**(開発/試遊ビルド限定)、実機 fps・draw call の計測と品質ティア。
7. **決定の見直し**: 下の一覧のとおり。

### やらないこと(スコープ外)

- **離す=スイング(パワプロ式)の操作**(ゲート1の回答で不採用。v2 のタップ方式を維持)。
- **打撃中の打者の顔を正面から映す別アングル**(カメラの再設計が必要。ユーザーは「投手の顔+後ろ姿+ワイプ」で補う案を採用した)。
- **スコアボードのイニングごとの得点表**(reducer に得点履歴が無いため。現在の得点・イニング・B/S/O のみ。次サイクルの候補)。
- **実在のブランド・商標の広告看板**(架空の名前のみ)。点光源による夜間照明(発光する材質で表す)。
- 外部素材(画像・GLTF・音声ファイル・外部フォント)、three addons(`EffectComposer`・`BufferGeometryUtils` 等。メッシュ統合は自前の関数。`SkinnedMesh`・`Skeleton`・`Bone` は three 本体で、addons ではない)、react-three-fiber。
- 実況(音声・`speechSynthesis`)、BGM、応援歌。効果音は短い合成音の効果音と歓声のノイズのみ。
- 左打者(全員右打ち。左右の鏡像は P1)。
- 横持ち(横画面)専用の構図(Q7 が確定するまで対象外)。デスクトップ(横長)は v2 のまま動くことだけを回帰で守る(縦長 ≤ 0.7 だけが v3 の新構図。補間域は v2 の `portraitBlendAt` のまま)。
- 守備操作(野手を動かす)、判定窓(±150ms)・ファウル窓・ジャスト窓・見逃し確定 D+250ms・タップ判定(180ms/10px)・到達通知の保留(≤ 200ms)の変更。
- 練習モード(打撃10球など)。初回のチュートリアル表示で代える。
- backend・`@sample-app/shared`・ホーム画面(`/`)・`home.spec.ts` の変更。
- 実機の自動検証(Playwright は headless のみ)。実機は人間の試遊と試遊ログで確認する。

## アーキテクチャ・変更概要

詳細は分冊(上の表)。本体には全体方針・検証・構成判断だけを置く。

### 全体方針

- 構成は v2 のまま `features/baseball/` の `types/`・`model/`・`render/`・`hooks/`・`ui/` を守る。`model/world/` は three 非依存の純粋関数、`from "three"` は `render/` のみ、`model/` と `render/` は互いに import せず、つなぐのは `hooks/` だけ([[frontend-3d-three-in-render-segment]])。**追加は `audio/` セグメント1つだけ**。キャラクターの純粋ロジックは `model/character/`、造形は `render/character/`。**最大の分は `model/stadium/`・`model/replay/`(純粋)、`render/stadium/`・`render/crowd/`(three)**。
- 新しいロジックはすべて純粋関数(`model/`)に切り出す([[pure-function-extraction]])。hooks と ui は薄いグルー。乱数は `Math.random` 禁止・シード付き PRNG か `seq`・スロット番号・インデックスのハッシュから導く決定論の関数([[sample-app-lint-random-and-index-access]])。
- 時計は v2 のまま1本(`usePitchFlight.getElapsedMs()`)。ゲージ(投球)はゲーム時計ではなく壁時計(`event.timeStamp`)で測り、`speed.timeScale` で割る。
- 判定は reducer の責務のまま。ただし投球の質(`PitchQuality`)と打撃のロックオン(`assistK`)は**判定への入力**として reducer・`resolvePitch` に渡す。キャラクターの見た目・走者の演出・スライディング・観客・時間帯・リプレイは**表示専用**(`GameState` に戻らない。例外: 進塁の事実 `lastAdvance` を state に記録するのは表示のためで、判定・乱数には使わない)。**リプレイは reducer に触れず、`sceneFrameAt` を保存した入力で再合成するだけ**。
- **ブラウザ保存(`localStorage`)に依存しない**: ユーザーは公開アーティファクト(claude.ai の sandbox iframe)で遊んでいる可能性があり、iframe では `localStorage` が例外を投げ、clipboard・ダウンロードも使えないことがある。設定・説明の既読・試遊ログ・品質ティアは、**メモリを主**とし、`localStorage` は `try/catch` で守った**任意の保存**にする。
- **契約は段階ごとに凍結**: A0(段階 A・B・C の型)、E0(段階 E の型と `render/character/parts.ts`)、M0(段階 M の型と `render/stadium/parts.ts`)。詳細は contract 分冊 §5。

### 4. 検証の作り直し

#### 4-1. 人間代理ボット v2(打撃。タップ方式)

v2 のボット(`model/sim/bot-sim.ts`)の欠点を直した、**個人差のある複数の仮想プレイヤー**。`model/sim/human-bot.ts`(+PA シミュレータ `human-game.ts`)に置く(テスト専用層)。乱数は mulberry32。

**1 人の仮想プレイヤーのパラメータ**(レベルごとの分布から 1 人 1 組サンプルし、レベルあたり 40 人 × 各 2000 球。結果は P10/P50/P90 で見る):

| パラメータ | 意味・根拠 | 初心者 | 中級 | 上級 |
| --- | --- | --- | --- | --- |
| `reactMs` | 見て動き出すまで(反応時間 200〜250ms。batting.md) | N(280, 40) | N(230, 30) | N(190, 25) |
| `biasMs`(リング有り) | 到達の知覚の偏り(正 = 遅く感じて遅くタップ)。リングが収束を明示するので v2 より小さい**と仮定した値(根拠なし。T1・T2 のログで較正する)** | N(+40, 45) | N(+15, 35) | N(0, 25) |
| `biasMs`(リング無し = v2 設定) | looming のみ。**調査(batting.md 2.5)の値 +130ms 前後で固定**。検出力テストを通すために動かしてはならない | N(+130, 50) | N(+130, 50) | N(+100, 40) |
| `timingSigmaMs` | タップの押下時刻のばらつき | 85 | 60 | 40 |
| `latencyMs` | 表示+入力の遅延(端末) | N(80, 20) | N(80, 20) | N(70, 15) |
| `fingerSigmaPx` | カーソルの最終位置の指のぶれ | 12 | 8 | 5 |
| `perceiveSigmaZone`(予告 exact) | 予告の点の位置の知覚誤差(ゾーン単位) | 0.18 | 0.10 | 0.06 |
| `swingAtStrike` / `chaseBall` | ストライク/ボール球を振る率の基準 | 0.80 / 0.30 | 0.85 / 0.20 | 0.90 / 0.12 |
| Fitts の `a, b, W` | `MT = a + b·log2(1 + 距離px / W)`(a=120ms, b=140ms/bit, W=40px) | 同 | 同 | b=110 |
| **失敗の型(タップ方式で生じる)** | | | | |
| `slowTapRate` | 押下が 180ms 超の長押しになり、スイングにならない確率/振る球 | 0.06 | 0.03 | 0.01 |
| `driftTapRate` | 押す瞬間に 10px 超動いてスイングにならない確率/振る球 | 0.05 | 0.025 | 0.01 |
| `cancelRate` | pointercancel でスイングが無くなる確率/球 | 0.02 | 0.01 | 0.005 |
| `ignoreRing` | リングを使わず、v2 と同じ知覚(リング無しの `biasMs`)で打つ人の割合 | 0.25 | 0.15 | 0.05 |
| `secondFingerRate` | カーソルを合わせた指のまま 2 本目の指/ボタンで振る割合(3 動作の「離す」を省く。合わせた後のタップの余分な待ち時間 = 0) | 0.20 | 0.35 | 0.50 |

(離す=スイング案の `takeRelease`・`regripRate` は、方式を採らないので削除した。)

**知覚の定義**:
- **ボール/ストライクの見分け**: 予告(exact)の知覚位置 = 真の着弾 + N(0, perceiveSigma)。ゾーンの外か内かを、知覚位置と「境界の余白(N(0.15, 0.2))」で判断して振る/見送る。予告なし(v2 設定)では、2D 画面の座標から等速で外挿して着弾を逆投影する(奥行きの推定誤差が出る。`camera/project.ts`)。2 ストライクでは境界を広げる(ゾーン外 +0.4 まで振る)。
- **カーソルの動き**: `reactMs` 後に動き出し、Fitts の移動時間で目標へ向かう(間に合わなければ途中位置でタップ)。**開始位置は前の球で最後にあった位置**。ロックオンは**押下時刻の有効カーソル**の式をそのまま使う。1 本指の場合は「合わせる → 離す → タップ」の 3 動作の時間(離して再度置くまでの追加の遅れ N(120, 30)ms)を足す。`secondFingerRate` の割合では追加の遅れが無い。
- **タップの時刻**: `press = D + biasMs + latencyMs + N(0, timingSigmaMs)`。判定時刻は `swingAtMs`(押下の時刻 − 70ms)。到達(D+250ms)の後の押下は無視(見逃し)。長押し・ドリフト・pointercancel は上の確率でスイングが無くなる。
- **出力(レベルごと、P10/P50/P90)**: 打率(安打 ÷ (打席 − 四球))、三振率、四球率、コンタクト率、ストライクを振る率・ボールを振る率、**押したのにスイングにならなかった率**、押下の時刻の平均と SD、カーソルと着弾点の距離の中央値(px)。

**PA シミュレータ**: `reduce`(CPU 投手→ボットのスイング/見逃し)を直接駆動し、カウント・四球・三振を含めた打席結果を数える。

**検出力テスト(前回の再発防止の核)と調整先の限定**: ボットは「v2 設定」(`ASSIST_OFF`: ロックオン 0・予告 `none`・リングなし・`biasMs` はリング無しの値・タップ入力)で、**前回ユーザーが「打てない」と評価した状態を再現できなければならない**。受け入れ: 初心者の打率 P50 ≤ .17 かつコンタクト率 P50 ≤ 50%、中級の打率 P50 ≤ .22。**E1 を通すための調整は、v3 の帯(E2〜E7)にも同じ値で効く共有パラメータ(`timingSigmaMs`・`fingerSigmaPx`・`reactMs`・Fitts・`perceiveSigmaZone`・失敗の型)に限り、「リング無し」の `biasMs` は調査の値で固定する**。同じ母集団を E2〜E7 にも適用する。再現できなければ、人間らしい範囲(上表の ±30%)で共有パラメータを調整し、調整の推移を完了報告に書く。

**悲観シナリオ**: リング有りの `biasMs` を「リング無しの値と上表の値の中間」(初心者 +85)にしても、初心者の打率 P50 ≥ .15・コンタクト率 P50 ≥ 45% を要求する。満たさなければ、値の推移を完了報告に出して設計の見直しとして上申する。

**実機ログでの較正**: 試遊ログ(4-3)の `fitBotParams(records)` が、押下時刻の平均・SD、距離の中央値、`tap-too-long`・`tap-moved`・pointercancel・入力種別(2 本目の指/ボタンの割合)から `biasMs`・`timingSigmaMs`・`fingerSigmaPx`・失敗の型・`secondFingerRate` を推定して出力する。A14 は、T1 のログが得られていればそれで分布の中心を較正する。**段階 E の後(E11)にボットのテストを再実行する**(投手 scale 1.30 でゾーンが約 23px 下がるため。外れたら A14b で再較正)。

**ボットテストの時間予算**: 通常のテストは縮約(1 レベル 30 人 × 1000 球)で実行し、帯は統計誤差を見込んで引く。完全版(40 人 × 2000 球)は環境変数 `BOT_FULL=1` のときだけ。1 ファイル 60 秒以内、ファイルを分けて並列に回し、全体の増加は 90 秒以内を目標とする。

#### 4-3. 実機の試遊ログ(開発/試遊ビルド限定。localStorage に依存しない)

- **有効化**: `import.meta.env.DEV` または `VITE_PLAYTEST=1` でビルドしたときだけ。
- **記録の置き場**: **メモリ(`useRef` のリングバッファ、最大 600 件)を主**とし、`localStorage`(`bb-playtest-v1`)への保存は `try/catch` で守った**任意**(失敗・容量超過は握りつぶさず、パネルに「保存できません(このまま画面から取り出してください)」と出す)。外部送信なし・個人情報なし。
- **記録の内容**:
  - 打撃 1 球ごと: 球種・D・着弾点・予告モード・難易度/アシスト、**スイングの入力種別(タップ/2 本目の指/ボタン/キー/マウス)・押下の時刻・`atMs`・`dtMs`・素のカーソル・有効カーソル(押下時刻のもの)・`assistK`・カーソルとボールの距離(d と px)・指の総移動量・タップの持続と移動量**、結果。スイングしなかった球は「見逃し」とその着弾がゾーン内か。
  - **スイングにならなかった入力**: 理由(`not-ready` / `holding` / `tap-too-long` / `tap-moved` / `cancel` / `held-release`)・時刻・**pointercancel の回数と時刻**。
  - 投球 1 球ごと: 狙い・着弾・ゲージの停止時刻と誤差 `errMs`・質・結果。
  - 共通: セッション ID、端末情報(`innerWidth/Height`・`devicePixelRatio`・`pointer: coarse`・`visualViewport.scale`・UA)、飛行中の fps(rAF の間隔の中央値・p95・落ちたフレームの割合)、**品質ティアとその切替・観客の体数・リプレイ中の p95**、顔のラスタ生成の所要時間(参考値)。
  - 起動時 1 回: `renderer.info.render.calls` と三角形数(`StageHandle.stats()`)。
- **取り出し(タイトルの「試遊ログ」)**: **必ず動く経路は「画面表示」**: 要約表と、**全選択できる `<textarea readonly>`(JSON)**。加えて「コピー」(`navigator.clipboard`)、「ダウンロード」(`.json` と `.csv`)、「共有」(Web Share)、「消去」。sandbox の iframe で使えない経路はボタンを無効化せず、失敗を表示する。画面が縮小表示されている疑い(`innerWidth ≥ 900` かつ `pointer: coarse`)を警告する。
- **診断の使い方**: 人間が 20 打席(約 60 球)遊んでログを渡す → `summarize(records)` の出力で「打てない原因」を切り分ける(診断表は [tests 分冊](2026-10-27-baseball-game-v3-tests.md) の末尾。タップ方式の理由の行を含む)。

#### 4-4. 実機 fps・draw call の計測と品質ティア

- 計測: (1) `StageHandle.stats()` で draw call・三角形数・観客の体数(起動時+各投球の最初のフレーム)、(2) `hooks/useFramePerf` で飛行中の rAF 間隔(中央値・p95)。いずれも試遊ログに入る。
- **目標**: 実機で T0 のとき、打撃の飛行中の fps の中央値 ≥ 50、p95 のフレーム時間 ≤ 28ms。満たさない端末は自動でティアが下がる(character 分冊 §3-4-10、max 分冊 §3-5-10。切替は飛行中を避ける。重い場合は 2 段降格)。T3 でも p95 > 33ms なら、ログに警告を残して人間に報告する(ゲート2で判断)。

既存 feature `features/baseball/` への追加で、構成判断は次の点: (1) **新セグメント `audio/`**(`render/` と同格の副作用アダプタ)。(2) **`model/character/`・`render/character/`**(`SkinnedMesh` 方式の造形と `parts.ts` 契約)。(3) **`model/stadium/`・`model/replay/`(純粋)、`render/stadium/`・`render/crowd/`(three)**(最大。`StadiumParts`/`CrowdParts` 契約は M0)。顔・番号・看板・スコアボード・芝・空の RGBA は `model/` が純粋関数で作り(node で画素を検査できる)、`render/` はその配列から `DataTexture` を作るだけ(`CanvasTexture` は `document` が要るため使わない)。つなぐのは `hooks/` だけ(`useCharacterLooks`・`useReplay`・`useStadiumState`)。**この環境では `frontend-designer` サブエージェントを呼び出せなかったため、構成案は本書で決めた**。`design-reviewer` がセグメント境界の妥当性を確認すること。構造検査(tests 分冊 1〜17)に追加済み。

## リスク・トレードオフ

- **規模(57 ステップ。最大の追加は 14 ステップ・4 ウェーブ・約 45 ファイル)**: 設計時の見込み(最大 = 約 10 ステップ・2 ウェーブ)より大きい。段階の順序(A → E → B → C → M → D)と各段階の終わりの全体緑で、M を別サイクルに回しても A・E・B・C・D が成立する(M の型は M0 で独立)。許容できなければ度合いを標準に戻す(ユーザーが最大を選択済みなので、戻す場合はゲート1で再確認する)。
- **打撃・守備のカメラでは球場の上段・観客・スコアボード・照明塔・ダグアウトは映らない**(HUD の裏か画面外。max 分冊 §3-5-1 の検算)。球場の作り込みの効果は追跡カメラ(HR)・内野カメラ・リプレイ・イントロで見える。**ユーザーが「打撃中も観客・スタンドがよく見えること」を期待していると食い違う**ので、ゲート1の承認時に伝える(構図の再設計が要る)。
- **`SkinnedMesh` 方式の妥当性は未検証**(この環境では three のソースを読めなかった)。E5 が確認事項 6 項目を検証し、致命的なら予算を実部品数(≈ 200)で計算し直して上申する。M21 のモックで早めに検証できる。
- **描画負荷(最大を含む)**: キャラクター ≈ 41 + 最大 +約 10 + 球場の既存分(未実測)。T0 ≤ 215 draw call の目標は E11・M13 の実測で確定する。観客 480 体の CPU 更新(約 0.3ms/フレーム)は小さいが、リプレイ中の負荷は p95 でログに残す。自動降格(重い場合は 2 段)・飛行中は切り替えない・初期ティアの復元で緩和。
- **顔のラスタ生成が実機で 100ms を超えうる**: 飛行中は生成しない・1 フレーム 1 体・先読み(イントロの 2 秒も使う)・仮の顔で進行を止めない。
- **ワイプとリプレイの負荷**: ワイプの第 2 パスは対象キャラ+背景だけ(≤ 12)。リプレイはシーンを再合成するだけで追加のメッシュは無いが、観客と土煙が映る。T2 は 0.5 倍速・1 カメラ、T3 は出さない。
- **投手を scale 1.30 にするとゾーンが約 23px 下がり、リリース点が変わる**。A14 のボット結果が E3 の後で変わりうるので、A14 を E3 より先に確定し、E11 で再実行する(外れたら A14b)。倍率は構図の倍率として追跡/内野カメラでは 1.0 へ戻す。
- **投球フォーム 3 種(標準)の差が小さい**: 手先を共通のリリース点の 0.15m 以内に収める制約。最大の固有フォームも同じ制約を守る。フォーム別のリリース点は軌道・S300・ボットの前提が変わるので採らない。
- **位置ずれ表示(DOM のミニ図)が追跡カメラの画面でボールに重なる**: 線だけ・半透明にして緩和し、D3 の連写で HR・ライナー・ゴロを確認する。
- **打者を小さくしてバット軸を伸ばす**(L = 1.35)ので、体とバットの比率が不自然に見える可能性がある。頭の右端はヘルメット込みで約 109px(ゾーン左端まで約 9px)。D3 が調整する。
- **タップ方式の限界(Q1 の選択)**: 「ドラッグで合わせる → 離す → タップ」の 3 動作の重さが残る(v2 の「打てない」の一因)。ロックオン・予告・リング・2 本目の指/ボタンの案内・ヒントで緩和し、T1 のログ(入力種別・`tap-too-long`・`tap-moved`)で効果を測る。**効果が不足した場合は、操作方式の再相談が要る**(ユーザーが選択済みなので、勝手に変えない)。
- **スキップに使った指はスイングできない**(v2 の仕様を維持): 離してもう一度タップ、または 2 本目の指/ボタン。`held-release` を数えて T1 で見直す。
- **アシストで打撃が易しくなりすぎる**: `qualityPenalty` と難易度の差で緩和し、A14 が帯に合わせる。
- **ボットは代理にすぎない**: 検出力テスト・悲観シナリオ・失敗の型で楽観を抑えるが、パラメータは仮定。T1・T2 の試遊ログで較正する。主観が「打てない」なら不合格。
- **試遊ログの取り出し**: sandbox の iframe では `localStorage`・clipboard・ダウンロードが使えないことがある。メモリを主・画面の `<textarea>` を必ず動く経路にして緩和。
- **投球の操作が 2 ジェスチャでテンポが遅くなる**(約 3.6 秒/球)。許容できなければゲージなし(案 D)に落とせる。
- **守備のドラッグが実機でスクロール・pointercancel で壊れる**: 守備中も `touch-action: none` 等を入れた。試遊ログの pointercancel の回数で確認する。
- **テンポの悪化**: 走者が動くヒットは +最大 3.0 秒(スライディングを含む。スキップ可。D3 が `runners.msPerBase` で調整)。リプレイは任意(ボタン)で、既定ではテンポに影響しない。イントロは試合開始の 2 秒(スキップ可)。
- **夜の視認性**: ボールのハロー・縁取り・予告の色が夜の色の膜で見えにくくならないか。D3 と T1c で確認する。
- **音のチープさ・iOS の制限**: デモ(M13)で事前に聴く。ユーザー操作として認められるイベントで `unlock`。
- **CPU 打者の変更で CPU 同士の打率が下がる**: B3 が出発値を調整して `balance.test` の基準を保つ。seed は D2 で再探索。
- **段階導入のコスト**: 段階 A の守備は旧格子 UI を新コマンドへ変換して維持する(使い捨ての変換が A13 に入り B6 で消える)。ファイルを段階ごとに再編集するので、同じファイルの変更が 2〜5 回に分かれる(並列では触らない規則で衝突は避ける)。
- **型変更で typecheck が赤い期間**: A0〜A12、E0〜E10、M0〜M12(出荷しない。A13・E11・M13 で緑)。
- **ヒットストップ・ズームパンチ・シェイク**は酔い・頭痛の懸念。`prefers-reduced-motion` で無効(時間帯の補間・観客の動きも)。

## ロールバック方針

- 変更は contract 分冊の「変更ファイル」に閉じる(DB・外部システム・データ移行なし。`localStorage` のキー `bb-tutorial-v1`・`bb-prefs-v1`・`bb-playtest-v1` はゲーム内だけ)。問題が出たら PR 単位で `git revert` する。ホーム(`/`)と `home.spec.ts` には影響しない。
- 部分的な切り戻し: (1) **操作**: v2 のタップ方式を維持しているので、A4・A9 の追加(理由の分類・押下時刻のロックオン)を戻すだけ。(2) **アシスト**: `ASSIST_TABLE` の `lockStrength` を 0・`preview` を `"none"`(リングと視認性の改善は残る)。(3) **構図**: `battingCameraPortrait` の x と `actors.batter.portrait*` を v2 の値(−0.25 / −0.65 / 0.92 / 1.0)に戻し、`actors.pitcher.scale` を 1.0・`RELEASE_POINT` を v2 の値に戻す。(4) **投球**: `gauge.sigmaScale` をすべて 1.0 にし windows を ∞ にするとゲージが無効。(5) **音・触覚・ログ**: 設定の既定を OFF にする/`VITE_PLAYTEST` を付けない。(6) **キャラクター**: 品質ティアを固定で T3 にすると v2 並みの負荷になる。顔・個性・フォームは `PlayerLook` の既定と v2 相当のフォームへ戻せる。走者・送球は `PitchOutcomeView.runners` を `null` にすると出ない。(7) **位置ずれ表示**: `zoneFeedback` を `null` にすれば出ない。(8) **最大(段階 M)**: ティアを固定で T3 にすると観客・土煙・ランプ・リプレイ・イントロが出ない。リプレイは `shouldOfferReplay` を常に偽にすると出ない。時間帯は設定「昼」で固定すれば色の膜・夜の発光が無くなる。固有フォームは `SignatureForm` を全員同じ既定にすれば標準のフォームに戻る。段階 M を PR ごと revert しても A・E・B・C・D は成立する。
- 判定・バランスは、元の値に戻せば v2 の挙動に戻る(`bot-balance.test` の帯は戻した値に合わせて見直す)。
