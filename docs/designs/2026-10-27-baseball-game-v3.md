## 要旨(先に読む)

- **何を直すか**: v2 修正版は自動テスト全合格・ボット安打率 33%・コードレビュー PASS で通ったが、ユーザーがスマホで遊ぶと「打てない」「投げるのもカス」「パワプロに程遠い」と不合格になった。さらにゲート1用のモックを見たユーザーが「パワプロじゃねーだろうが全然」と言い、**キャラクターの見た目(顔・表情・頭身・ユニフォーム・動き)が最大の不満の一つ**と分かった。調査の結論は、(1) 打撃は**着弾点が事前に分からず、振る合図が無く、操作の説明も無い**、(2) 投球は**人間の腕前が結果に効かない**、(3) 画面は**打者の後頭部が画面の半分を占め、キャラクターは顔も表情も個性も無い同一人形で、音が一切ない**、(4) **検証が人間の代理になっていなかった**。
- **v3 の基本線(調査の案C = P0 に、キャラクターの作り直しを本体として加える)**: 打撃の骨格(着弾点の予告・縮むリング・ロックオン・「離した瞬間がスイング」・ボールの視認性・初回の説明)、投球の骨格(ゾーンを直接なぞって狙い、縮むリングにタップを合わせるゲージで質が決まる)、**キャラクターの作り直し(顔・8 種の表情・髪型・ヘルメット/帽子・ユニフォームの番号・選手ごとの個性・肘と膝のあるフォーム・走者の3D化・捕球と送球・顔アップのワイプ。外部素材なし、three のメッシュ+コード生成テクスチャ)**、見た目・手応え(打者を小さく端へ・カットイン/バナー・Web Audio の合成効果音・振動・位置ずれ表示)、検証の作り直し(人間代理ボット v2・投球ボット・実機の試遊ログ)。
- **覆す v2 の決定**: 「タップでスイング」(Q-A)、「サウンドはやらない」、「初心者アシストはやらない」、「守備側の操作改善はやらない」、「縦長カメラ x −0.25(Q-B)」、**「キャラクターは同一モデル・顔なし」「走者の3D表示・送球はやらない」**。**維持**: 外部素材禁止、three addons 不使用、チームごとの色、タップでの演出スキップ、演出の後に更新、ホーム画面のレイアウト、見逃し確定 D+250ms。
- **実装は 5 段階(A 打撃の骨格 → E キャラクター → B 投球の骨格 → C 演出・音 → D 検証・調整)**で、**42 ステップ**。各段階の終わりに全体が緑になる。**A の完了時点で打撃だけが遊べるビルドを人間に渡し(中間試遊 T1)、E の完了時点でキャラクターの見た目を人間に確認してもらう(T1b)**。ゲート2の前に、ボット以外の「人間が実機で遊ぶ」確認を必ず入れる。
- **描画負荷の設計**: キャラクターを豊かにしても、メッシュ統合・LOD・顔は 1 体 1 枚のテクスチャで、キャラクターの draw call を v2 の約 350 から約 120 に減らす。実機 fps が足りないときは、自動で品質を 4 段階(影・画素比・キャラの簡略化)に落とす。

## 目的・スコープ

### 目的

スマホで遊んで、**打てる・投げられる・パワプロっぽい手応えと見た目がある**ブラウザ野球にする。自動テストの数値(特に v2 のボット)を人間の根拠にせず、「人間が遊んで楽しいか・見て『それっぽい』か」を受け入れ基準の中心にする。

### v2 で何が起きたか(前回の失敗と再発防止)

| 前回の失敗 | 原因 | v3 での再発防止(本書の該当箇所) |
| --- | --- | --- |
| 打率 33% のボットが合格だったのに人間は「打てない」 | ボットが (a) ストライクだけ振る (b) 到達時刻を偏りなく知覚する (c) 着弾点を 3D の直線外挿で完全に推定する (d) 指の移動・持ち替え時間が無い (e) 個人差が無い(調査 batting.md 2.6) | 「検証 — 人間代理ボット v2」: 見分け誤り・知覚の偏り・2D からの推定誤差・Fitts の法則・**個人差の分布(P10/P50/P90)**・**v3 で新たに生じる失敗の型**を入れ、**v2 設定で「打てない」を再現できること(検出力テスト。調整先は共有パラメータに限る)**と**悲観シナリオ**を受け入れ基準にする |
| 守備側(投球)は腕前が結果に効かないまま、検証も無かった | 投球の結果は狙いセル中心にガウス誤差を足すだけ(pitching.md) | 投球の腕前(狙いの精度+ゲージ)を結果に効かせ、**投球ボット**で「上手い人ほど抑えられる」を数値で守る |
| 見た目・音が「やらないこと」に落ちたままゲート1を通った(`visual-scope-must-be-shown-at-gate1` の再発) | サウンド・カットイン・構図・キャラクターの作り込みを「スコープ外」にして承認を得た | 「ゲート1で人間に見せるもの」に、**実描画のモック(構図の数値つき)・操作の流れ図・音のデモ・ロックオン強度の表・キャラクターの度合い別モックの作り方**を列挙する。**キャラクターは本体に入れ、度合いをユーザーに選んでもらう** |
| 実機で遊ぶまで不満が見えなかった | 実機の入力・体感のデータが無い | 「実機の試遊ログ」(端末内に記録、**localStorage に依存せず画面から取り出せる**)と「遊べる版を人間に渡すタイミング(T1・T1b・T2)」を設計に入れる |

### やること(P0)

1. **打撃の骨格**: ①着弾点の予告(`exact`/`fade`)②縮むリング(到達の先行合図。枠の発光は結果の合図として残す)③ロックオン(難易度で強さを変える。ふつうは初心者が打てる既定)④**操作を「触れる→スライド→離した瞬間がスイング」に**(ボタン・2本目の指・キー・マウスと共存)⑤ボールの視認性(最小径・縁取り・ハロー・縫い目と回転)⑥初回のチュートリアル表示と、最初の数球の画面内ヒント。
2. **投球の骨格**: 調査の案 C(ゾーン直接ドラッグ+ゲージ)の簡略版を採る(理由は「投球の骨格」節)。狙い→ゲージ(縮むリングをタップで止める)→質(ナイス/グッド/ふつう/失投)が着弾のばらつきを決める。狙いと着弾の重ね表示、windup の短縮、1球のテンポ短縮、CPU 打者の反応(位置・質)。
3. **キャラクターの作り直し(本体。「キャラクターの作り直し」節)**: 2〜2.5 頭身のデフォルメを保ったまま、顔(目・眉・口・頬)・8 種の表情・髪型・ヘルメット/帽子・肌色・体格・ユニフォームの質感と背番号・選手ごとの個性・肘と膝のあるフォームのキーフレーム・走者の3D化と進塁・野手の捕球と送球・顔アップのワイプ(カットイン)。**外部素材なし**。描画予算と品質の自動切替を設計に含める。
4. **見た目・手応え**: 打撃・守備の構図(打者を小さく端へ、守備はゾーンを大きく、投手を大きく)、カットイン/バナー演出、接触演出(ヒットストップ・カメラの食いつき)、位置ずれ表示、Web Audio の**合成効果音**(外部素材なし)、振動(Android のみ)、音・振動のミュート設定。
5. **検証の作り直し**: 人間代理ボット v2、投球ボット、検出力テスト、**実機の試遊ログ**(開発/試遊ビルド限定)、実機 fps・draw call の計測と品質ティア。
6. **決定の見直し**: 下の一覧のとおり。

### やらないこと(スコープ外)

- **「最大」の度合いの項目**(Q-char で「最大」が選ばれない限り): スライディング・ベースカバー、選手別の固有フォーム(標準は投手 3 種・打者 3 種の共有フォーム)、観客の動き、球場の作り込み(広告・照明塔・時間帯・天候)、リプレイ。
- 外部素材(画像・GLTF・音声ファイル・外部フォント)、three addons(`EffectComposer`・`BufferGeometryUtils` 等。メッシュ統合は自前の関数)、react-three-fiber。
- 実況(音声・`speechSynthesis`)、BGM、応援歌。効果音は**短い合成音の効果音と歓声のノイズ**のみ。
- 左打者(全員右打ち。左右の鏡像は P1)。
- 横持ち(横画面)専用の構図。デスクトップ(横長)は v2 のまま動くことだけを回帰で守る(縦長 ≤ 0.7 だけが v3 の新構図。補間域は v2 の `portraitBlendAt` のまま)。
- 守備操作(野手を動かす)、判定窓(±150ms)・ファウル窓・ジャスト窓・**見逃し確定 D+250ms(入力イベントの時刻で判定)**の変更。
- 練習モード(打撃10球など)。初回のチュートリアル表示で代える(練習モードは P1 の候補)。
- backend・`@sample-app/shared`・ホーム画面(`/`)・`home.spec.ts` の変更。
- 実機の自動検証(Playwright は headless のみ)。実機は人間の試遊と試遊ログで確認する。

### 決定の見直し一覧(v2 → v3)

v2 設計の「やらないこと」・ゲート1の決定・規約と、v3 の施策のぶつかる箇所を一覧にする。**覆すものは人間がゲート1で承認する**。

## アーキテクチャ・変更概要

### 全体方針

- 構成は v2 のまま `features/baseball/` の `types/`・`model/`・`render/`・`hooks/`・`ui/` を守る。`model/world/` は three 非依存の純粋関数、`from "three"` は `render/` のみ、`model/` と `render/` は互いに import せず、つなぐのは `hooks/` だけ([[frontend-3d-three-in-render-segment]])。**追加は `audio/` セグメント1つだけ**。キャラクターの純粋ロジックは `model/character/`(新規。`model/` 直下のサブフォルダ)に置く。
- 新しいロジックはすべて純粋関数(`model/`)に切り出す([[pure-function-extraction]])。hooks と ui は薄いグルー。乱数は `Math.random` 禁止・シード付き PRNG か `seq`・スロット番号から導く決定論の関数([[sample-app-lint-random-and-index-access]])。
- 時計は v2 のまま1本(`usePitchFlight.getElapsedMs()`)。ゲージ(投球)はゲーム時計ではなく壁時計(`event.timeStamp`)で測り、`speed.timeScale` で割る。
- 判定は reducer の責務のまま。ただし投球の質(`PitchQuality`)と打撃のロックオン(`assistK`)は**判定への入力**として reducer・`resolvePitch` に渡す。キャラクターの見た目・走者の演出は**表示専用**(`GameState` に戻らない。例外: 進塁の事実 `lastAdvance` を state に記録するのは表示のためで、判定・乱数には使わない)。
- **ブラウザ保存(`localStorage`)に依存しない**: ユーザーは公開アーティファクト(claude.ai の sandbox iframe)で遊んでいる可能性があり、iframe では `localStorage` が例外を投げ、clipboard・ダウンロードも使えないことがある。設定・説明の既読・試遊ログ・品質ティアは、**メモリを主**とし、`localStorage` は `try/catch` で守った**任意の保存**にする。

### 1. 打撃の骨格

#### 1-1. 操作(触れる→スライド→離した瞬間=スイング)

v2 との差と共存を表にする(「ステージ」= 入力面 `bb-stage__input`)。**狙いの指(aiming)は `pointerId` で管理する**(「1本目」を `isPrimary` で決めない)。

| 入力 | v3 の動作 | v2 との差 |
| --- | --- | --- |
| タッチ pointerdown(演出中 = `holding`) | スキップ。この指は「持ち越しの指(held)」になる | 同じ |
| タッチ pointerdown(狙いの指が**いない**) | その指が**狙いの指(aiming)**になる。**カーソルは動かさない**(相対ドラッグ) | v2 の「タップ候補」「1本目」を廃止。`isPrimary` ではなく「狙いの指がいるか」で決める |
| タッチ pointerdown(狙いの指が**いる**。2本目以降) | 現在のカーソル位置で**即スイング**(押した時刻。`swingReady` でなければ何もしない) | 同じ |
| タッチ pointermove(狙いの指) | 指の移動量だけカーソルが動く(1:1。ロックオンで補正される) | 同じ |
| **タッチ pointerup(狙いの指)** | `swingReady` かつ**離したイベント時刻が D−300ms 以上 D+250ms 以下**ならその時刻でスイング(動かさずに離した場合も同じ)。それ以外は何もしない(理由は試遊ログに記録: `late` = 見逃し、`regrip` = 持ち替え、`not-ready`、`holding`) | **新**(v2: ≤180ms・≤10px のタップだけがスイング) |
| 持ち越しの指(held)・取り残された指 | **演出が終わった時点で狙いの指に昇格**する(狙いの指がいなければ。相対ドラッグの起点は昇格時点のその指の位置とカーソル位置)。以後は通常の規則(離すとスイング) | **新**: v2 の「演出中に置いて動かさなかった指は離しても振れない」を直す |
| 狙いの指が離れた/キャンセルされたとき他の指が下りている | その指は、次の pointermove で狙いの指に昇格する | 新 |
| スイングボタン pointerdown | 即スイング(押した時刻)。狙いの指がいても押せる | 同じ(両手持ち用の補助) |
| マウス move / pointerdown | 絶対位置で追従 / 押した時刻でスイング | 同じ |
| キー(矢印/WASD、Space/Enter、Z/X) | v2 のまま | 同じ(`defaultPrevented` の排他も同じ。[[dom-key-input-exclusivity]]) |
| pointercancel | スイングしない(狙いを捨てる。回数を試遊ログに記録) | 同じ |

- **離した時刻の判定**: `atMs = (離した pointerup の timeStamp − リリース時刻)×timeScale − 70ms`(`swingAtMs` に `origin = {timeStamp: 離し, sourceTimeStamp: 離し, inputKind: "touch"}` を渡す。式は v2 §2 のまま)。**受理の判定はイベント時刻 `eventMs = (離し − リリース)×timeScale`(遅延補正前)で行う**: `eventMs > D + lateCutoffMs(250)` なら**スイングにせず見逃し**(即座に到達通知)。ボタン・2本目の指・キー・マウスが保留中に処理された場合も同じ基準(`useBattingControls.swingNow` が `eventElapsedMs(origin)` を見る)。
- **見逃し = 指を離さず待つ**: 人は球が過ぎたのを見て反応 200〜250ms 後に離すので、離す時刻は D+250 以降に集まる。この離しは締切を過ぎているので**見逃し**になり、空振りストライクにならない。チュートリアル・ヒントに「見逃すときは 指を はなさずに まつ」を入れる。
- **持ち替え(早い離し)**: 離したイベント時刻が **D−300ms より前**(窓 ±150ms・遅延補正 70ms・余白 80ms を足した、当たる可能性が無い時刻)の離しは、持ち替えとみなして**スイングにせず無視**する(ヒント「リングが ● に かさなるまで 指を はなさない」を最大 3 回まで出す)。D−300ms〜D−150ms の離しは「早い −xxx ms」の空振りとして返す。マウス・ボタン・2本目の指・キーには適用しない。
- **到達通知の保留**: 狙いの指が下りている間は、到達通知(見逃しの確定)を **D + `lateCutoffMs`(250) + `aimGraceMs`(120)まで**保留する。**これは離しの処理が描画で遅れても、イベント時刻が締切内の離しを落とさないため**で、保留中に D+250 を超えたイベント時刻の離しは上の規則で見逃しになる。保留は純関数 `arrivalDue` が毎フレーム判断する。
- **スイング種別(ミート/強振)**: ボタン・Z/X キーのまま。
- **守備中のステージもスクロール・長押しを無効にする**: `.bb-stage__input--active`(`touch-action: none`)は人間打撃中だけでなく**人間守備中も付ける**。`-webkit-touch-callout: none`・`-webkit-user-select: none` を付け、ステージの `contextmenu` を `preventDefault` する。Playwright の touch エミュレーションでは再現できないので、**試遊ログに pointercancel の回数と時刻・離しが無視された理由を記録**する。

#### 1-2. 着弾点の予告(`preview`)と縮むリング(先行合図)

投球がリリースされた瞬間(`flight` の出現。t = 0)から、**着弾点に予告の印**を出し、その周りに**D に向かって縮むリング**を出す。リリース前(windup 中)は着弾点が決まっていないので出さない(`CPU_PITCH` の dispatch がリリース時のため。残り約 1.3 秒ある)。

- **リング**: 着弾点(ゾーン平面)を中心に、半径が t = 0 で `startRadius`(0.30m。390 幅で約 89px)、t = D で `endRadius = ballRadius × 1.25 = 0.125m`(約 37px。ボールの縁のすぐ外)になる**線形**の縮小(D 以降は D の半径で保持)。**ボールが着弾点に着いた瞬間にリングがボールを囲む**。これが「先行する今の合図」(v2 のゾーン枠の発光は D−20ms からの結果の合図で、反応時間 200ms 超の人間には使えなかった)。ゾーン枠の発光は残す。線幅は画面で約 3px(「画面上の px の扱い」)。
- **点の見せ方は難易度で変える**(アシストの `preview`): `exact` = 着弾点の真上に小さな点(半径 0.04m・シアン・黒縁)。`fade` = フェードカーソル(点は出さず、半径 `fadeRadius` の薄い円を、着弾点から `seq` から決まる決定論のずれ `fadeJitter` 以内で動かした位置に出す。円は必ず真の着弾点を含む)。`none` = 点も円も出さない(リングは出る。ボットの v2 設定とロールバック用)。**色はシアン(0x5ce1ff)**にして、黄色のカーソルと区別する。
- **変化球**: 予告は**最終の着弾点**(`flight.landing`)に出す。軌道の曲がりは従来どおり(誇張なし)。
- **ボール球かストライクかは、予告の点がゾーン枠の内か外かで分かる**(ふつうまで)。
- 出現は 120ms でフェードイン(`fadeInMs`)。D + `hold`(接触なしは消失時刻)まで残す。

#### 1-3. ロックオン(カーソルの補正)とアシストの強さ

ロックオン = 指で動かした「素のカーソル」(`raw`)を、飛行中に着弾点へ**部分的に引き寄せた「有効カーソル」**を判定と表示の両方に使う(表示と判定は常に同じ有効カーソル)。

```
progress p = clamp(t / D, 0, 1)
dist       = ゾーン単位での raw と landing の距離(ユークリッド)
capture    = 1 − smoothstep(captureRadius, captureRadius × 1.6, dist)   // 遠すぎるボールは引き寄せない
ramp       = smoothstep(rampStart, rampEnd, p)                          // 早い時刻は素のカーソル、終盤で効く
k          = lockStrength × capture × ramp
effective  = raw + (landing − raw) × k
```

- 判定に使うカーソルは `effective`(`SwingInput.cursor`)。`SwingInput.assistK = k` も渡す。**質 q は `k` が大きいほど下げる**: `q' = q × (1 − qualityPenalty × k)`(補助なしの上手い人のほうが強い打球を打てる)。
- 難易度ごとの出発値(`ASSIST_TABLE`。A14 がボットで調整してよい):

| 難易度 | lockStrength | captureRadius(ゾーン単位) | rampStart / rampEnd | preview | fadeRadius / fadeJitter | qualityPenalty |
| --- | --- | --- | --- | --- | --- | --- |
| かんたん | 0.80 | 1.6 | 0.30 / 0.80 | exact | — | 0.30 |
| **ふつう(既定)** | **0.55** | **1.2** | 0.35 / 0.85 | exact | — | 0.35 |
| むずかしい | 0.20 | 0.7 | 0.40 / 0.90 | fade | 0.45 / 0.25 | 0.40 |

- アシストは**難易度に連動**する(新しい設定 UI は作らない)。「むずかしい」も縮むリングと視認性の改善は入る。

#### 1-4. ボールの視認性と「画面上の px の扱い」

モック(M2・M3)で、**最小径にしても白い投手の服の前では輪郭が弱い**ことが分かった。ハローを必須にし、縫い目は「見える距離」を現実的に定めた。

| 項目 | v2 | v3 |
| --- | --- | --- |
| 飛行中の最小表示径 | 無し(リリース 7.5px) | **飛行中も最小表示径**: `ballScaleFor(camera, ball, minRatio)` に飛行用の `minScreenDiameterRatioFlight = 0.0175`(390×844 で約 14.8px)。リリース直後は約 2.0 倍、**D−730ms 付近**で 1 倍に戻る(連続・単調) |
| 縁取り | 球の 1.12 倍の黒い殻 | 殻の太さを**画面で 2px 以上**に保つ(`outlineScaleFor`。`ball.outlineScale`) |
| 白い服との重なり | 重なる | **ハロー(必須)**: 球の 1.9 倍の暖色(#ffd9a0)の半透明円(不透明度 0.35)を球の後ろに敷く。ハローは常に表示し、輪郭と合わせて背景によらず見える。モックで「不十分」なら `halo.opacity` を 0.5 まで上げる(D3 が調整) |
| 縫い目・回転 | 無し | **太い赤い帯(球の径の 18% 幅の弧 2 本)**と**回転**。**径 15px 前後(飛行の前半)では帯の回転がかろうじて分かる程度で、縫い目の形が見えるのは D 付近(径 30px 以上)**。前半の手がかりは最小径・ハロー・予告のリングとし、球種の見分けは D−700ms 以降の回転と球種チップ・球速で行う(完了条件も「D−700ms 以降で認識できる」程度) |
| 位置の手がかり | 影(円盤1つ) | 影は残す。予告の点とリングが主役 |

**画面上の px の扱い**: 「画面で 2px 以上」「線幅 3px」は、px ではなく**画面高さに対する比**(`shellMinRatio = 0.0024`・`ringWidthRatio = 0.0036`。844px で 2px・3px)で `WORLD_PARAMS` に置き、`model/world/camera/rig.ts` の `outlineScaleFor`・`ringWidthFor(camera, point, widthRatio)` が `ratio × 2 × dist × tan(fov/2)` で m に換算して `SceneFrame.ball.outlineScale`・`SceneFrame.guide.ring.width`(m)に入れる。render は受け取った値をそのまま使う。

#### 1-6. スイング後の位置ずれ表示と、接触後のカメラ(モック所見 4)

v2 の接触後はカメラが 500ms かけて中継カメラに移るので、「スイング後 900ms の 3D の十字と輪」はそのままでは見えない(ゾーンが画面から消える)。**決定**:

- **接触後もカメラを打撃位置に残す時間 `chaseDelayMs = 300ms`** を入れる(`PlayPlan.chaseFromMs = contactMs + hitStopMs + 300`)。この間、打球は打撃カメラから遠ざかって見え、3D の位置ずれ表示(白い十字・シアンの輪・線)が見える。空振り・ファウルでも 3D の位置ずれ表示は `feedbackMs`(900ms)出す(ファウルは打球カメラへ移らない範囲)。
- 接触ありの場合の 3D 表示は `feedback3dMs = 300ms`(chaseDelay の間)で、その後は **DOM のタイミングのピル(2 行目の「芯/ふつう/かすり」)と結果バナーの副文**に引き継ぐ(ピルは `zoneRect`(打撃カメラのゾーン矩形)に追従する DOM なので、カメラが動いても位置が変わらない)。
- テンポの代償: 接触ありの 1球が +300ms(スキップ可)。

### 2. 投球の骨格(案 C の簡略版: ゾーン直接ドラッグ+リングゲージ)

**選択肢(調査 pitching.md)と選択**

| 案 | 内容 | 腕前の要素 | パワプロらしさ | 工数 | v3 の判断 |
| --- | --- | --- | --- | --- | --- |
| A 現行改善 | 格子は残し windup 短縮・重ね表示・σ 調整 | 無し | 低 | S〜M | 採らない(腕前が戻らない) |
| B ゲージ追加 | 格子+ゲージ | ゲージ | 中 | M〜L | 採らない(格子は遠く間接的) |
| **C ゾーン直接ドラッグ+ゲージ** | ゾーンをなぞって狙い、離して確定、ゲージをタップで止める | **位置+ゲージ** | **高** | L | **採用(簡略版)** |
| D ワンジェスチャ | 押したまま動かして離して投げる | 位置のみ | 中 | M〜L | 採らない(誤タップ・腕前が弱い) |

**採用理由**: (1) 打撃の操作(ゾーンを相対ドラッグ+縮むリング)と同じ言語になり、1つのチュートリアルで済む。(2) 腕前が2要素(位置の精度・タイミング)で結果に効く。(3) ゾーンが大きく見える構図にでき、格子を操作バーから外すので画面が空く。

**流れ(人間守備)**

```
[球種チップを選ぶ] (常時。球速と曲がり矢印つき)
        ↓
(idle) ステージに指を置く → (aiming) 狙いの照準が出る。スライドで動く(相対ドラッグ、散布円で「ブレの目安」を表示)
        ↓ 指を離す(= 狙いを確定)
(gauge) 照準の周りのリングが 900ms かけて縮む(戻らない。終点を過ぎても 300ms は縮み続ける)
        ↓ リングが照準に重なる瞬間にタップ(ステージのどこでも / 「とめる!」ボタン / Space)
(throwing) 質が決まる(ナイス / グッド / ふつう / 失投) → windup 280ms → 投球 → 飛行 → 着弾
        ↓
着弾から 700ms: 狙い(白の照準)と着弾(シアンの点)を重ねて表示 + 「ナイスピッチ!」「ズレ 0.2」等
```

- **質の決まり方**: ゲージの誤差 `e = (停止時刻 − 入力種別の遅延補正) − (ゲージ開始 + 900ms)`。遅延補正は入力の種類別(タッチ 70ms・マウス/キー 20ms)。`|e| ≤ 40ms` = ナイス、`≤ 90ms` = グッド、`≤ 160ms` = ふつう、それ以外・タップなし(自動投球)= 失投。**ゲージ開始から `stopGuardMs`(250ms)は停止を受け付けない**(ダブルクリックが失投になるのを防ぐ)。
- **着弾のばらつき**: v2 の σ(`baseSigma 0.28 × 制球 × 疲労`、人間の制球 63 で約 0.384)に質の倍率を掛ける: ナイス ×0.35 / グッド ×0.65 / ふつう ×1.0 / 失投 ×1.7 かつ**狙いを真ん中やや高め(0, 0.15)へ 60% 引き寄せる**。乱数の消費数は変えない(ガウス 2 回のまま)。
- **質ごとの「狙いと着弾のずれ」の見え方(モック所見 6。ゲート1では文で補う)**: 平均のずれ(σ√(π/2)、ゾーン単位 → 390×844 で 1 単位 ≈ 77px)は、ナイス ≈ 0.17(≈ 13px。照準と点がほぼ重なる)、グッド ≈ 0.32(≈ 25px。点が照準の輪の縁)、ふつう ≈ 0.48(≈ 37px。輪の外)、失投 ≈ 0.8 + 真ん中への引き寄せ(≈ 65px 以上。大きく外れて「甘い」)。重ね表示の点と線は、ナイスでも見えるよう**照準の輪を細く(外周 44px・線幅 2px)、着弾の点を径 24px のシアン**にし、距離のラベル(「ズレ 0.2」)を添える。M10 のモックは**ナイスのケースだけ**なので、ふつう・失投の絵(上の距離で)を追加で作る(ゲート1の資料)。
- **狙いは連続座標**(ゾーン単位。±1.67 に制限)。`PitchCommand` を `{ kind, aim: ZonePoint, quality }` に変え、CPU は `CpuPitchChoice { kind, cell }` を返し、reducer がセル中心を `aim` に直して `quality: "normal"` で投げる。
- **PC・キー**: マウスは動かすと狙いが追従、クリックで確定、もう一度クリック(または Space)で停止。キーは矢印で狙いを動かし、Space/Enter で確定→停止。「投げる」ボタン(`throw-pitch`)は、`idle`/`aiming` では「確定」、`gauge` では「とめる!」を同じ操作として受ける。
- **入力面の受け持ち**: 守備中の `bb-stage__input` のポインタイベントは `usePitchingControls` が受け、打撃中は `usePointerInput` が受ける(`useGameStage` が人間打撃/守備のモードで選ぶ)。**演出中のスキップは守備でも `routeStagePointer`(`holding` なら `skip`)を先に通す**。`usePitchingControls` は座標変換のため `pickZone`・`getZoneRect` を注入で受ける(自分では `getBoundingClientRect` を使わない)。
- **球種チップ**: 球種名・球速・曲がり矢印。1つ 76×52px。常に選べる。

**CPU 打者との整合**

- `PitchFlight.quality` と着弾位置の「縁度」(`extent = max(|x|, |y|)`)で、CPU 打者の入力ノイズを変える。`cursorSigma × qualityFactor × locationFactor`、`timingSigmaMs × (qualityFactor^0.5) × locationFactor'`。`qualityFactor` = ナイス 1.7 / グッド 1.25 / ふつう 1.0 / 失投 0.65(難易度の `qualitySensitivity` で冪にする: かんたん 1.2 / ふつう 1.0 / むずかしい 0.6)。`locationFactor = 1 + 0.9 × max(0, extent − 0.5)`、`locationFactor' = 1 + 0.4 × max(0, extent − 0.5)`。失投は振る確率も ×1.25(上限あり)。
- **同じ球種の連投は不利**にする: 直前の球種が同じなら `cursorSigma` を ×0.85。
- CPU 同士(`balance.test.ts`)も位置・質に反応するので打率が下がる。B3 が出発値を調整し、**`balance.test.ts` の基準は変えない**。

**テンポ**: 人間の windup 700ms → **280ms**、CPU の windup 700ms → **550ms**、テロップ: ボール 500 → 380ms、空振り 700 → 520ms、ファウル 700 → 520ms、インプレー 1100 → 900ms、余韻 200 → 120ms。**1球の所要(スキップなし)の式**: `windup + D + (人間打者で指が無い見逃し: lateCutoffMs / CPU 打者: 前倒し分を引いて 0)+ テロップ + 余韻`。ストレート(D = 1310ms)の CPU 投手・人間打者の見逃しで 550 + 1310 + 250 + 380 + 120 ≈ **2.6 秒**(v2 は約 3.0 秒)、カーブ(D = 1652ms)は +342ms。指を下ろしたままの見逃しは +120ms。**接触ありは +300ms(chaseDelay)、走者が動くヒットは +最大 3.0 秒(走者の進塁。スキップ可)**。人間の投球は(狙い 約 0.5 秒+ゲージ 約 1.0 秒+windup 0.28+飛行 1.33+結果 0.5)で約 3.6 秒。

### 3-4. キャラクターの作り直し(本体。段階 E)

ユーザーがモックを見て「パワプロじゃねーだろうが全然」と言った。モック([m1-batter-options.jpg](assets/2026-10-27-baseball-game-v3/m1-batter-options.jpg) ほか)でも、打者は顔のない大きな後頭部、投手は小さな円筒の人形で、全員が同じ形・同じ髪のない頭・目だけの顔(+z 側の黒い点)のままだった。調査 visual.md の B(キャラクター)・C(モーション)系の施策(B1 造形・B2 選手ごとの見た目・B3 顔と表情・C1 フォーム・C3 走者の3D表示・E1 カットイン)を、**外部素材なし・three のメッシュ+コード生成テクスチャ**で実現する。パワプロの画像・造形・名称・ロゴは模倣しない(「みたいな」に留め、自前の意匠にする)。

#### 3-4-1. 比率とデフォルメ

- 現行の頭身は全身 2.05m ÷ 頭 0.92m ≈ **2.2 頭身**で、パワプロのデフォルメ(2〜2.5 頭身。visual.md §3 No.1)と同じ方向。**頭身は変えない**(受け入れ: 全身の高さ ÷ 頭の高さが 2.0〜2.6。体格バリエーションを含む)。差は「顔が見えない・動かない・全員同じ」ことにある。
- **体格(`build`)**: slim(胴・脚の幅 ×0.9)・normal(×1.0)・stocky(×1.15)と、身長 ×0.96〜1.04 の個人差。頭の大きさは固定。

#### 3-4-2. 顔(1 体 1 枚のテクスチャ)

- 頭は少し縦長の球(x 1.0・y 0.95・z 0.95)+あご(小球)+耳(小球 2 個)。**顔の領域**は頭の前面の球面パッチ(水平 ±55°・垂直 −35°〜+30°。z ファイティングを避けるため半径 ×1.003・`polygonOffset`)で、`MeshBasicMaterial({ map, transparent })`。
- **顔アトラス**: 1 体 1 枚の `DataTexture`(RGBA)。**96×96 のセルを 4×2 = 8 表情**(384×192、約 295KB/体)。表情の切替は**テクスチャの `offset`(UV)だけ**を変える(再アップロードなし)。`CanvasTexture` は使わない(`document` に触れるのは `stage.ts` のみの規約を保つため)。代わりに **`model/character/raster/` の純粋関数が SDF(符号付き距離)で目・眉・口・頬・汗・星などを描いて RGBA の `Uint8Array` を返し**、`render/` は `DataTexture` にするだけ(node で画素を検査できる)。画質がモックで不足なら、`stage.ts` が `createCanvas` を注入する案(`CanvasTexture`)に切り替える(設計の見直しとして上申)。
- **目鼻口の寸法(出発値。頭の幅 = 1)**: 目は 1 つあたり幅 0.14・高さ 0.20 の縦長の楕円(黒目・白目・ハイライト)で、中心間隔 0.36、高さは顔領域の上から 45%。眉は幅 0.16(`thin` 0.02 厚・`thick` 0.045 厚・`angled` 傾き ±15°)。口は幅 0.18。頬は赤みの楕円。**目の形(`eyes`)は 4 種**(round 丸・sharp つり目・droopy たれ目・big 大きな目)。
- **表情 8 種(`FaceExpression`)**: `neutral`(普通)、`focus`(眉を寄せ口一文字。構え・投球前)、`effort`(歯を食いしばる。投球のリリース・スイング)、`shock`(目が丸く口を開ける。空振り・打たれた)、`joy`(目が ^ ^ で口を開けて笑う。打った・抑えた)、`cheer`(大きく笑って頬を上げる。ホームラン・三振を取った)、`sad`(眉が下がり口がへの字、汗。三振・打たれた・四球)、`blink`(目を閉じる。まばたき)。まばたきは `neutral` の間に周期約 2.8 秒・120ms で自動(位相は**スロット番号から決まる決定論**)。

#### 3-4-3. 髪・ヘルメット・帽子

- 髪(`hair.style` 6 種: short・side(横分け)・long(後ろ髪が長い)・round(丸刈りに近い丸い髪)・buzz(坊主)・ponytail)。低ポリ(1 種 ≤ 120 三角形)で、後ろ髪・もみあげ・うなじがヘルメット/帽子の下から見える。**打者の後ろ姿(打撃カメラ)で最も目立つのはここ**。色 `hair.color`(5 色)。
- **打者はヘルメット**(チーム色。右耳のフラップ・ツバ)、**投手・捕手・野手・走者は帽子**(パネルの縞・つば・マーク。つばは前に突き出て顔に影を落とす)。v2 の「全員が帽子」をやめる。

#### 3-4-4. ユニフォームの質感と背番号

- 上着・ズボン・ストッキング(チーム色+白線)・靴・ベルト・グローブを、**頂点カラー**で塗り分ける(裾・脇を暗くする擬似的な陰影)。トゥーン材質の階調は v2 のまま。ピンストライプ(`Team.pinstripe`)のチームは、胴に**縞の `DataTexture`(64×64、チームごとに 1 枚を共有)**を貼る。
- **背番号**: `model/character/raster/number.ts` が 0〜99 の太い数字(自前の 5×7 グリッドのビットマップフォントを拡大)を RGBA に描き、胴の背中側に貼る 64×48 の小さなクアッド(1 体 1 枚、背番号とチーム色の組でキャッシュ)。打撃カメラの打者は横〜後ろ向きなので、背番号と髪・耳が「誰か分かる」手がかりになる。

#### 3-4-5. 選手ごとの個性(`PlayerLook`)

- `Team.pitcher.look`・`Team.batters[i].look`(`types/team.ts` に加算。表示専用)。`PlayerLook = { number, skin(0〜4), hair{style,color}, build, eyes, brow, restMouth, pitchForm, batStance }`。**2 チーム × (打者 9 + 投手 1)= 20 人全員で (髪型, 髪色, 肌, 体格, 目の形) の組が異なり、背番号がチーム内で一意**(受け入れ L3)。
- **守備側の割り当て**: 守備チームの打線の 9 人が守備位置に就く(投手 = `Team.pitcher`、捕手 = 打線 8 番目、一〜右 = 打線の 0〜6 番目から固定の対応表)。走者は攻撃側の打線の該当選手(`lineupIndex` から遡って塁に出ている選手。表示だけなので「走者 n 人目 = 直前の打者」の簡易な対応でよい)。

#### 3-4-6. フォーム(肘と膝のあるリグ+キーフレーム)

- **リグの拡張**(`CHARACTER_RIG`・`CharacterRig`・`JointPose`): 腕を上腕と前腕(`elbowL/R`)、脚を大腿と下腿(`kneeL/R`)に分ける(関節 6 → 10)。FK(`motion/fk.ts`)・`pose-apply` を追従。
- **投球フォーム 3 種(`pitchForm`)**: over(オーバー)・three-quarter(スリークォーター)・side(サイド)。各フォームでリリースの手先が `RELEASE_POINT` の 0.15m 以内(FK で検査)。投手を **scale 1.30**(§3-1)にするので、`RELEASE_POINT` は FK の結果で更新する。
- **打撃の構え 3 種(`batStance`)**: open・square・crouch(縦長の構図でゾーン枠・格子に手が掛からない構え。v2 の H13 の縦長の構えを基にする)。スイングのキーフレーム(接触以降)は共有。
- **野手**: 待機(膝に手)・走り・**捕球(グローブを落下点へ上げる)**・**ゴロ捕球(かがむ)**・**送球(オーバースロー)**。**走者**: リード(塁から半歩)・走り・喜び(ガッツポーズ)。**感情のポーズ**: 三振の打者のうなだれ、抑えた投手のガッツポーズ。
- 選手別の固有フォーム(各 5 種以上)は「最大」。

#### 3-4-7. 表情のタイムライン(純関数 `expressionAt`)

`expressionAt({ role, phase, plan, tMs, slotIndex })` が、役割・演出の局面・結果から表情を返す。

| 役割 | 待機 | windup〜飛行 | 結果 |
| --- | --- | --- | --- |

#### 3-4-8. 走者の3D化・捕球・送球(標準)

- **走者**: `SceneFrame.runners`(固定 4 体: 打者走者・一塁・二塁・三塁)。進塁の事実は `GameState.lastAdvance`(reducer が結果の適用時に記録する加算フィールド)から `PitchOutcomeView.runners = { before, after, scored, batterTo, advances }` を作り、`model/world/path/runners.ts` が塁間の経路上の位置と時刻を決める。**1 塁進むのに 1.6 秒、全体で最大 3.0 秒**(複数塁は速度を上げて収める)。ホームランは走者を動かさない(カメラが打球を追うため。バナーで表す)。**スキップで即終了**。
- **進塁を見せるカメラ**: 打球の追跡カメラ(外野を追う)では走者が見えないので、**落下後に走者が動くプレーでは、高い内野のカメラ(`infieldCamera`。位置 (0, 22, 10)・注視 (0, 0, −20) の出発値)へ 400ms で blend**し、走者の進塁が終わるまで保持する(`model/world/camera/infield.ts`)。走者が動かないプレー(フライアウトなど)は blend しない。
- **捕球・送球(表示のみ。判定には関与しない)**: フライ/ライナーのアウト = 野手が捕球ポーズ。ゴロのアウト = 野手が捕ってかがみ、一塁へ送球(ボールが 0.7 秒で一塁へ。一塁手が捕球。打者走者はアウトで止まる)。併殺打 = 二塁→一塁の 2 回送球。ヒット = 野手が球に追いつき(落下点で止まる)、送球はしない。**演出と結果の矛盾を避ける**ため、結果ごとの演出の表を `model/world/path/fielders.ts` に置き、`world-consistency.test` で全結果に対して「アウトのとき送球のボールが走者より先に着く・安打のとき走者が先に着く・得点数と本塁に着いた走者の数が一致」を守る。スライディング・ベースカバーは「最大」。
- **テンポ**: 走者が動くヒットは +最大 3.0 秒。スキップ可。受け入れ G4 は走者が動く場合を別基準にする(後述)。

#### 3-4-9. 顔の向きの検討と、顔アップのワイプ(カットイン)

**検討(モック所見 7 と方針)**: 打撃カメラ(捕手の後方)で、**打者が顔を投手側へ向けたまま顔が見える構図は成立しない**。理由: 右打者はこちらに背を向けて(横向きで)打席に立ち、顔は投手 = 画面の奥(−z)を向く。カメラは捕手の後方(+z 側)にあるので、顔の向き(−z)とカメラへの向き(+z 側)の角度は、カメラをどう横にずらしても(x = ±1.2m で約 146°)90° 未満にならない。胴の向き(yaw)を開いても、首を投手側へ向ける限り同じ。つまり、後ろから見える頭は「後頭部・耳・もみあげ・ヘルメットのフラップ」であり、**パワプロの打撃画面も打者は後ろ姿**(顔が見えるのはカットインとリプレイ)。

したがって次の 4 つで「顔が見える」を満たす:

1. **投手の顔が正面で見える**(打撃カメラ・守備カメラとも投手は捕手側を向いている)。**投手を scale 1.30**(頭径 ≈ 44px)にして表情が読めるようにする(§3-1)。
2. **打者の後ろ姿を作り込む**(髪・耳・ヘルメット・背番号・体格。§3-4-3〜5)。
3. **打席に入る前のルーティン**: 待機(idle。windup の前)の打者は、顔をカメラへ向けた 3/4 の向き(`neutral`/`focus`)で立ち、投手の windup が始まると構えへ向き直る(`batter` の yaw と head を `idle→stance` でキーフレーム補間。純関数)。顔が画面左端で見える短い時間を作る。
4. **ワイプ(顔アップ。第 2 ビューポート)**: **同じシーンを別のカメラで小さな矩形に再描画**する(新しいメッシュは増えない)。打者の顔は**投手側から見る**(カメラを打者の 2.2m 前・投手寄りに置く。顔が正面に映る)、投手の顔は捕手側から見る。`SceneFrame.wipe = { visible, target: CharacterSlot, rect, alpha }`、カメラの姿勢は `model/world/camera/wipe.ts` の純関数が決める(顔の向きとカメラの前方の内積 ≤ −0.6 を単体テストで守る)。`render/stage.ts` が `setScissor`/`setViewport` で第 2 パスを描く。**出す場面**(900〜1400ms): 打席の紹介(打者の顔・番号・名前。非ブロッキング)、ヒット(打者走者の joy)、ホームラン(cheer)、三振(打者 sad・投手 cheer)、ナイスピッチ(投手 joy)。矩形は縦長 390×844 で x 290〜384・y 175〜269(94×94px。ボールの通り道 x 118〜273 と HUD(y < 155)を避ける)。DOM の縁取り・名前・背番号は `ui/CutIn.tsx`。品質ティア 3 では出さない。

#### 3-4-10. 描画予算と品質ティア

### 4. 検証の作り直し

#### 4-1. 人間代理ボット v2(打撃)

v2 のボット(`model/sim/bot-sim.ts`)の欠点を直した、**個人差のある複数の仮想プレイヤー**。`model/sim/human-bot.ts`(+PA シミュレータ `human-game.ts`)に置く(テスト専用層)。乱数は mulberry32。

**1 人の仮想プレイヤーのパラメータ**(レベルごとの分布から 1 人 1 組サンプルし、レベルあたり 40 人 × 各 2000 球。結果は P10/P50/P90 で見る):

| パラメータ | 意味・根拠 | 初心者 | 中級 | 上級 |
| --- | --- | --- | --- | --- |
| `reactMs` | 見て動き出すまで(反応時間 200〜250ms。batting.md) | N(280, 40) | N(230, 30) | N(190, 25) |
| `biasMs`(リング有り) | 到達の知覚の偏り(正 = 遅く感じて遅く離す)。リングが収束を明示するので v2 より小さい**と仮定した値(根拠なし。T1・T2 のログで較正する)** | N(+40, 45) | N(+15, 35) | N(0, 25) |
| `biasMs`(リング無し = v2 設定) | looming のみ。**調査(batting.md 2.5)の値 +130ms 前後で固定**。検出力テストを通すために動かしてはならない | N(+130, 50) | N(+130, 50) | N(+100, 40) |
| `timingSigmaMs` | 離す時刻のばらつき | 85 | 60 | 40 |
| `latencyMs` | 表示+入力の遅延(端末) | N(80, 20) | N(80, 20) | N(70, 15) |
| `fingerSigmaPx` | カーソルの最終位置の指のぶれ | 12 | 8 | 5 |
| `perceiveSigmaZone`(予告 exact) | 予告の点の位置の知覚誤差(ゾーン単位) | 0.18 | 0.10 | 0.06 |
| `swingAtStrike` / `chaseBall` | ストライク/ボール球を振る率の基準 | 0.80 / 0.30 | 0.85 / 0.20 | 0.90 / 0.12 |
| Fitts の `a, b, W` | `MT = a + b·log2(1 + 距離px / W)`(a=120ms, b=140ms/bit, W=40px) | 同 | 同 | b=110 |
| **失敗の型(v3 で新たに生じる)** | | | | |
| `takeRelease` | 見送る球で、**指を下ろしたまま D + reactMs に離してしまう**確率。離す時刻が D+250 以内ならスイング扱い | 0.35 | 0.15 | 0.03 |
| `regripRate` | 飛行中に**持ち替え**(D−300ms より前に離す)する確率/球 | 0.08 | 0.04 | 0.01 |
| `cancelRate` | pointercancel でスイングが無くなる確率/球 | 0.02 | 0.01 | 0.005 |
| `ignoreRing` | リングを使わず、v2 と同じ知覚(リング無しの `biasMs`)で打つ人の割合 | 0.25 | 0.15 | 0.05 |

**知覚の定義**:
- **ボール/ストライクの見分け**: 予告(exact)の知覚位置 = 真の着弾 + N(0, perceiveSigma)。ゾーンの外か内かを、知覚位置と「境界の余白(N(0.15, 0.2))」で判断して振る/見送る。予告なし(v2 設定)では、2D 画面の座標から等速で外挿して着弾を逆投影する(奥行きの推定誤差が出る。`camera/project.ts`)。2 ストライクでは境界を広げる(ゾーン外 +0.4 まで振る)。
- **カーソルの動き**: `reactMs` 後に動き出し、Fitts の移動時間で目標へ向かう(間に合わなければ途中位置で離す)。**開始位置は前の球で最後にあった位置**。ロックオンは有効カーソルの式をそのまま使う。
- **離す時刻**: `event = D + biasMs + latencyMs + N(0, timingSigmaMs)`。**イベント時刻が D+250 を超えたら見逃し扱い**(実装と同じ受理判定。保留 +120ms は処理遅延の吸収なのでボットでは使わない)。判定時刻は `swingAtMs`(`− 70ms`)。持ち替えガード(D−300ms)・pointercancel・見逃しの離しは上の確率で入れる。
- **出力(レベルごと、P10/P50/P90)**: 打率(安打 ÷ (打席 − 四球))、三振率、四球率、コンタクト率、ストライクを振る率・ボールを振る率、**見送る球での誤スイング率**、離す時刻の平均と SD、カーソルと着弾点の距離の中央値(px)。

**PA シミュレータ**: `reduce`(CPU 投手→ボットのスイング/見逃し)を直接駆動し、カウント・四球・三振を含めた打席結果を数える。

**検出力テスト(前回の再発防止の核)と調整先の限定**: ボットは「v2 設定」(`ASSIST_OFF`: ロックオン 0・予告 `none`・リングなし・`biasMs` はリング無しの値・タップ入力)で、**前回ユーザーが「打てない」と評価した状態を再現できなければならない**。受け入れ: 初心者の打率 P50 ≤ .17 かつコンタクト率 P50 ≤ 50%、中級の打率 P50 ≤ .22。**E1 を通すための調整は、v3 の帯(E2〜E7)にも同じ値で効く共有パラメータ(`timingSigmaMs`・`fingerSigmaPx`・`reactMs`・Fitts・`perceiveSigmaZone`・失敗の型)に限り、「リング無し」の `biasMs` は調査の値で固定する**。同じ母集団を E2〜E7 にも適用する。再現できなければ、人間らしい範囲(上表の ±30%)で共有パラメータを調整し、調整の推移を完了報告に書く。

**悲観シナリオ**: リング有りの `biasMs` を「リング無しの値と上表の値の中間」(初心者 +85)にしても、初心者の打率 P50 ≥ .15・コンタクト率 P50 ≥ 45% を要求する。満たさなければ、値の推移を完了報告に出して設計の見直しとして上申する。

**実機ログでの較正**: 試遊ログ(4-3)の `fitBotParams(records)` が、離す時刻の平均・SD、距離の中央値、持ち替え・pointercancel・見送りでの離しの率から `biasMs`・`timingSigmaMs`・`fingerSigmaPx`・失敗の型を推定して出力する。A14 は、T1 のログが得られていればそれで分布の中心を較正する。

**ボットテストの時間予算**: 通常のテストは縮約(1 レベル 30 人 × 1000 球)で実行し、帯は統計誤差を見込んで引く。完全版(40 人 × 2000 球)は環境変数 `BOT_FULL=1` のときだけ。1 ファイル 60 秒以内、ファイルを分けて並列に回し、全体の増加は 90 秒以内を目標とする。

#### 4-2. 投球ボット

`model/sim/pitch-bot.ts`。仮想プレイヤー(レベルあたり 40 人): ゲージのタップ時刻のばらつき `timingSigmaMs`(初心者 110 / 中級 70 / 上級 45)とバイアス(0 / +20 / 0)、指のぶれ `fingerSigmaPx`(10 / 7 / 5。ゾーン単位へは `pxPerZoneUnit` で換算)、配球戦略(初心者=ゾーン内をほぼ中央・同じ球種、中級=縁を 40%・球種を変える、上級=縁 60%+球種とコースを変える、「中央連打」=比較用)。ゲージ開始から 250ms 未満の停止は無視される。CPU 打者(ふつう)との PA を `reduce` で回し、被打率・ストライク率・四球率・ナイス率を出す。

#### 4-3. 実機の試遊ログ(開発/試遊ビルド限定。localStorage に依存しない)

- **有効化**: `import.meta.env.DEV` または `VITE_PLAYTEST=1` でビルドしたときだけ。
- **記録の置き場**: **メモリ(`useRef` のリングバッファ、最大 600 件)を主**とし、`localStorage`(`bb-playtest-v1`)への保存は `try/catch` で守った**任意**(失敗・容量超過は握りつぶさず、パネルに「保存できません(このまま画面から取り出してください)」と出す)。外部送信なし・個人情報なし。
- **記録の内容**:
  - 打撃 1 球ごと: 球種・D・着弾点・予告モード・難易度/アシスト、**スイングの入力種別・離した時刻・`atMs`・`dtMs`・素のカーソル・有効カーソル・`assistK`・カーソルとボールの距離(d と px)・指の総移動量**、結果。スイングしなかった球は「見逃し」とその着弾がゾーン内か。
  - **無視された入力**: 理由(`late` / `regrip` / `not-ready` / `holding`)・イベント時刻・**pointercancel の回数と時刻**。
  - 投球 1 球ごと: 狙い・着弾・ゲージの停止時刻と誤差 `errMs`・質・結果。
  - 共通: セッション ID、端末情報(`innerWidth/Height`・`devicePixelRatio`・`pointer: coarse`・`visualViewport.scale`・UA)、飛行中の fps(rAF の間隔の中央値・p95・落ちたフレームの割合)、**品質ティアとその切替**。
  - 起動時 1 回: `renderer.info.render.calls` と三角形数(`StageHandle.stats()`)。
- **取り出し(タイトルの「試遊ログ」)**: **必ず動く経路は「画面表示」**: 要約表と、**全選択できる `<textarea readonly>`(JSON)**。加えて「コピー」(`navigator.clipboard`)、「ダウンロード」(`.json` と `.csv`)、「共有」(Web Share)、「消去」。sandbox の iframe で使えない経路はボタンを無効化せず、失敗を表示する。画面が縮小表示されている疑い(`innerWidth ≥ 900` かつ `pointer: coarse`)を警告する(公開アーティファクトの HTML には viewport meta があることを確認済みなので、別環境・将来の退行の検出用)。
- **診断の使い方**: 人間が 20 打席(約 60 球)遊んでログを渡す → `summarize(records)` の出力で「打てない原因」を切り分ける(下表)。

| 症状(ログの値) | 疑う原因 | 打つ手 |
| --- | --- | --- |
| 離す時刻の平均 `dtMs` が +80ms 以上 | 到達の知覚の偏り・遅延補正の不足 | 遅延補正(70ms)の見直し、リングの見せ方 |
| `dtMs` の SD が 100ms 以上 | リズムが取れない(合図が弱い) | リングの太さ・音・球速 |
| 距離の中央値が 60px 以上 | カーソルが間に合わない・ロックオンが弱い | ロックオン強度・ドラッグの感度 |
| 離した入力が `touch-second`/`button` ばかり | 1 本指の「離す=スイング」が使われていない | チュートリアルの見直し |
| ボールを振る率が高い | 予告が読めていない | 予告の見せ方 |
| 無視された離しの `late` が多い | 見逃し時に指を離してしまう | ヒント・チュートリアル・締切の見直し |
| 無視された離しの `regrip` が多い | 持ち替えの多用 | ガード時刻・ヒントの見直し |
| **pointercancel が多い** | スクロール/コールアウト/端スワイプが効いている | `touch-action`・端のマージン・コンテキストメニュー抑止の見直し |
| fps の p95 が 33ms 超・品質ティアが下がった | 描画負荷 | 描画予算(ティア・メッシュ統合・影) |

#### 4-4. 実機 fps・draw call の計測と品質ティア

- 計測: (1) `StageHandle.stats()` で draw call・三角形数(起動時+各投球の最初のフレーム)、(2) `hooks/useFramePerf` で飛行中の rAF 間隔(中央値・p95)。いずれも試遊ログに入る。
- **目標**: 実機で T0 のとき、打撃の飛行中の fps の中央値 ≥ 50、p95 のフレーム時間 ≤ 28ms。満たさない端末は自動でティアが下がる(§3-4-10)。T3 でも p95 > 33ms なら、ログに警告を残して人間に報告する(ゲート2で判断)。**P1 の可否判断(v2 に無かった顔・走者の3D化を入れるか)は、キャラクターを必須にしたことでティアの切替に置き換わった**。

### E2E(Playwright。D2)

既存の 24 件を v3 の操作・DOM に合わせて更新し、次を追加する。**SwiftShader では実入力が 0.2〜1 秒以上遅れる**ので、時間窓を狙うテストは「ページ内で入力の `event.timeStamp`・飛行開始・D を記録し、アプリと同じ計算で有効試行だけを検証、無効は次の投球で再試行(最大 5 回)」にする([[swiftshader-playwright-input-latency]])。**前提**: tutorial 以外の spec は `addInitScript` で既読・球数ヒントの設定を入れる。試遊ログは `DEV` で常に有効なので、「入口が無い」確認は preview ビルドの別 project。

1. **離す=スイング(タッチ)**: ドラッグし、飛行中に離す → `data-timing` が出る。有効試行のときだけ `dtMs` を検証。
2. **持ち替えは捨てる**: D−300ms より前の離しでスイングにならない(ヒント)。D−300〜D−150ms は「早い」の空振り。
3. **見逃し(指を離さず待つ)**: イベント時刻 D+300 に離す → 見逃し。D+200 → 空振り(遅い)。D+400 → 見逃し。
4. **持ち越しの指**: スキップして指を置いたまま次の球で離す → スイング。
5. **追加の指・スイングボタン・Space**: v2 のテストを維持。
6. **予告とリング**: `data-guide="exact"`(ふつう)・`fade`(むずかしい)。リング半径が減る。
7. **投球**: PC・キー・ボタン(2 回目はゲージ開始から 250ms 以上後)で 1 球投げられ `data-pitch-quality` が出る。自動投球で失投になり試合が止まらない。ダブルクリックで失投にならない。守備の入力面の `touch-action` が `none`。
8. **チュートリアル**: 初回に出て閉じる。表示中は投球が始まらず、Space/Enter でスキップされず「つぎへ」がキーで押せる。
9. **音**: `AudioContext` を計数スタブに差し替え、最初の操作(`pointerup`/`click`/`keydown`)の後に `unlock`、1 球で cue が呼ばれる。ミュートで呼ばれない。音質は自動では検証できない。
10. **試遊ログ**: スイングごとに記録が増え、要約と `<textarea>` の JSON が出る。**`localStorage` が例外でも 1 試合が通る**。clipboard を無効化しても取り出せる。preview ビルドでは入口が無い。
11. **幾何**: 縦長 3 高さ+デスクトップ+タブレットの打撃・守備(バー ≤ 135/140px、格子がバーに掛からない、打者の頭の右端 ≤ 110px、ゾーンがオーバーレイと 4px 以上離れる)。`index.html` に viewport meta がある。
12. **キャラクター**: **結果に応じて役割ごとの表情が切り替わる**(`data-expr-pitcher`・`data-expr-batter`。三振で打者 `sad`・投手 `cheer`、ヒットで打者 `joy` など)。ヒットで走者が進塁し(`data-runner-*`)内野カメラへ移る。三振・ヒットでワイプが出て(`data-wipe`)、`?tier=3` で出ない。`?tier=<n>` で品質ティアが固定される(`data-quality-tier`)。
13. **回帰**: 1 イニング通し・WebGL 不可・スキップ・Enter/Space 長押しで再試合しない・`home.spec.ts`。seed は A14・B3・D1 の後に再探索する。

① スマホ縦で、打撃・守備の構図(打者が小さく端・ゾーンが中央・投手が顔と表情の読める大きさ)、予告の点とリング、ボールの見え方(ハロー)。② 1本指で「スライド→離す」で振れる、見逃すときに指を離さず待てる、持ち替えが誤爆しない、スキップした指をそのまま離せる。③ 守備でゾーンをなぞって狙い、リングに合わせてタップでき、狙いと着弾の重ね表示(ナイス・ふつう・失投の見え方)。スクロール・長押しのメニューが出ない。④ バナー・ヒットストップ・位置ずれ表示(接触後もゾーンが画面に残る 300ms)。⑤ 音・振動・ミュート。⑥ チュートリアル。⑦ **キャラクター: 顔・8 表情・髪・ヘルメット・背番号・20 人の個性・フォーム・走者の進塁・送球・ワイプ・品質ティアの切替**。⑧ ボットの出力(E・F 群)を完了報告に貼る。⑨ **実機の試遊ログ**。

### 「人間が遊んで打てるか・見て『それっぽい』か」の検証手順と、人間に渡すタイミング

1. **ボット(代理)**: 打撃・投球ボットの帯を満たす。**検出力テスト(E1)で前回の不合格を再現できること**・**悲観シナリオ(E10)と失敗の型(E11)**が前提。
2. **T1 — 中間試遊(段階 A の完了直後 = A13。段階 E・B・C の前)**: 試遊ビルド(`VITE_PLAYTEST=1`)を人間に渡す。**打撃 20 打席(約 60 球)**を遊び、画面の試遊ログ(JSON)をコピーして貼る(キャラクターは v2 のまま・守備・演出・音は未実装)。診断(4-3 の表)で原因を切り分け、ロックオン強度・予告・遅延補正・見逃し/持ち替えの規則・ボットの較正に反映する(A14。必要なら A1・A2・A4 を直す)。**ゲート1で承認を得る**(Q8)。
3. **T1b — キャラクターの確認(段階 E の完了直後 = E11)**: E11 のスクリーンショット(打撃・守備・表情・個性・フォーム・走者・ワイプ)と試遊ビルドを人間に渡し、「パワプロっぽいか」と足りない点を聞く(`AskUserQuestion`)。足りなければ E の調整(E2 の顔・E5 の造形・E3 のフォーム)を B の前に入れる。
4. **T2 — 最終試遊(`/test` 完了後 = ゲート2)**: 必須。**打撃 20 打席(約 60 球)と守備 20 球**を遊ぶ。合格の目安は、**人間の主観**(「打てた・投げられた・パワプロっぽい」/「微妙」/「打てない・違う」)と、ログの客観値(**最初の 20 打席**の目安: コンタクト率 ≥ 55%、ストライクを振る率 ≥ 70%、離す時刻の SD ≤ 100ms、距離の中央値 ≤ 60px、無視された離しのうち `late` + `regrip` ≤ 20%、fps の p95 ≤ 33ms(下回る場合は品質ティアの切替の記録を見る))。**主観が「打てない」「パワプロじゃない」なら、ボットが合格していても不合格**とし、ログの診断表で原因を特定して `/design` か `/implement` に戻る。
5. 試遊環境の確認: ログの端末情報と縮小表示の警告で、どの画面で遊んだかを記録する。公開アーティファクトの HTML には viewport meta がある(調査で確認済み)ので、`index.html` の viewport meta を E2E で固定するにとどめる。取り出しは画面の `<textarea>` が必ず動く。

### 操作の流れ図(M12 の元)

**打撃**:

```
[指を置く]──カーソルは動かない(相対ドラッグの起点。演出中に置いた指は演出後にそのまま狙いの指になる)
   │
[スライド]──指の移動量だけカーソルが動く。終盤はロックオンで ● に吸い寄せられる
   │  投球がリリースされた瞬間: ● と大きなリングが出る → リングが D に向けて縮む
   ▼
[リングが ● にぴったり重なる瞬間に 指を離す] = スイング
   │   判定時刻 = 離した時刻 − 70ms
   │   ※ D−300ms より前の離しは「持ち替え」で無視 / 見逃すときは指を離さず待つ(D+250ms を過ぎた離しは見逃し)
   ▼
結果: 「ジャスト!/早い −62ms/遅い +48ms」+「芯/かすり」+ 位置ずれ(十字と輪。接触後 300ms はカメラが残る)+ 打球音・振動
   ▼
打球カメラ → (走者が動くなら内野カメラ)→ バナー・ワイプ → タップでスキップ可 → 次の球
別の振り方: 追加の指をタップ(その場で即スイング)/ スイングボタン / PC はクリック・Space
```

**投球**:

```
[球種チップを選ぶ(常時)]
   ▼
[指を置く]──照準が出る → [スライド]──照準が動く(散布円がブレの目安) → [指を離す] = 狙い確定、ゲージ開始
   ▼
リングが 0.9 秒かけて照準に向けて縮む(過ぎても 0.3 秒は縮み続ける。開始から 0.25 秒は停止できない)
   ▼
[リングが照準にぴったり重なる瞬間に タップ(どこでも / 「とめる!」)]
   → 質: ナイス(±40ms)/ グッド(±90)/ ふつう(±160)/ 失投
   ▼
windup 0.28 秒 → 投球 → 着弾 → 狙い(白)と着弾(シアン)の重ね表示 + 「ナイスピッチ!」(質ごとのずれ: 13 / 25 / 37 / 65px 以上)
PC: マウスで狙い → クリック(確定)→ クリック/Space(停止)
```

## リスク・トレードオフ

- **キャラクターの作り直しの規模と負荷(標準)**: 11 ステップ・約 25 の新規ファイル。最大のリスクは(a)モバイル GPU の負荷(メッシュ統合・LOD・品質ティアで管理。目標の draw call はキャラクター ≤ 120・全体 T0 ≤ 250。**球場の draw call は未実測**なので、E11 の実測で目標を確定し、超えるときは球場側の統合も作業に入れる)、(b)**顔の画質**(96×96 のセルを SDF で描く自前のラスタで「パワプロっぽい」顔になるか。モック M16 で確認し、不足なら `createCanvas` を注入する `CanvasTexture` 案へ切り替える上申)、(c)走者・送球の演出と結果の矛盾(結果ごとの表と `world-consistency.test` で守る)。許容できなければ度合いを「最小」に下げる(§3-4-11)。
- **打撃カメラでは打者の顔は見えない**(幾何的に不可能。§3-4-9)。投手の顔・後ろ姿の作り込み・打席前のルーティン・ワイプで補うので、ユーザーの期待が「打撃中の打者の顔」だとずれる。モックで確認する。
- **投手を scale 1.30 にするとゾーンが約 23px 下がり、リリース点が変わる**(`RELEASE_POINT` の「固定」の例外)。E3 が FK で更新して軌道のテスト(S300 など)を再確認する。段階 A の完了時点(scale 1.0)の数値と E 完了後の数値が違う点は表で明示した。
- **打者を小さくしてバット軸を伸ばす**(L = 1.35)ので、体とバットの比率が不自然に見える可能性がある。モックでは推奨案で手とバットの根元が見えた。D3 が調整する。
- **離す=スイングの誤爆(Q1)**: D−300ms より前の離しは無視し、ヒントとチュートリアルで緩和。見逃しは「指を離さず待つ」作法で、締切 D+250ms を過ぎた離しは見逃し(空振りにならない)。ボットの `takeRelease` で誤スイング率を監視する。許容できなければ v2 のタップ方式に戻す(A4 を差し替え)。
- **アシストで打撃が易しくなりすぎる**: `qualityPenalty` と難易度の差で緩和し、A14 が帯に合わせる。
- **ボットは代理にすぎない**: 検出力テスト・悲観シナリオ・失敗の型で楽観を抑えるが、パラメータは仮定。T1・T2 の試遊ログで較正する。主観が「打てない」なら不合格。
- **試遊ログの取り出し**: sandbox の iframe では `localStorage`・clipboard・ダウンロードが使えないことがある。メモリを主・画面の `<textarea>` を必ず動く経路にして緩和。
- **投球の操作が 2 ジェスチャでテンポが遅くなる**(約 3.6 秒/球)。許容できなければゲージなし(案 D)に落とせる。
- **守備のドラッグが実機でスクロール・pointercancel で壊れる**: 守備中も `touch-action: none` 等を入れた。Playwright では再現できないので試遊ログの pointercancel の回数で確認する。
- **テンポの悪化**: 接触ありは +300ms(chaseDelay)、走者が動く安打は +最大 3.0 秒。いずれもスキップ可。D3 が `runners.msPerBase`(1.2〜2.0 秒)で調整する。
- **音のチープさ・iOS の制限**: デモ(M13)で事前に聴く。ユーザー操作として認められるイベントで `unlock`。
- **予告がリリースと同時**(windup 中には出せない): 残り約 1.3 秒あるので許容。
- **CPU 打者の変更で CPU 同士の打率が下がる**: B3 が出発値を調整して `balance.test` の基準を保つ。seed は D2 で再探索。
- **段階導入のコスト**: 段階 A の守備は旧格子 UI を新コマンドへ変換して維持する(使い捨ての変換が A13 に入り B6 で消える)。ファイルを段階ごとに再編集するので、同じファイルの変更が 2〜4 回に分かれる(並列では触らない規則で衝突は避ける)。その代わり、T1 で打撃の骨格を早く触れ、T1b でキャラクターを早く確認できる。
- **`SceneFrame`/`PitchCommand`/`PlaybackSpeed`/`CharacterRig` の型変更**で A0〜A12 の間は typecheck が赤い(出荷しない。A13 で緑)。
- **ヒットストップ・ズームパンチ・シェイク**は酔い・頭痛の懸念。`prefers-reduced-motion` で無効。
- **規模**: 42 ステップ・新セグメント 1 つ(`audio/`)・約 70 の新規ファイル。段階 C(演出・音)と段階 B(投球)は独立しているので、ゲート1で規模を調整する場合は C を後続の別サイクルに回せる(A0 の型契約に C の分を含めてあるので、その場合は C の型・定数を残して未使用にする)。キャラクターは Q-char で度合いを選べる。

## 未解決の疑問(ゲート1用に整理)

**ユーザーに決めてもらう 5 論点(Q-char・Q1・Q3・Q7・Q8)は冒頭の表**。以下は**推奨既定値で進める項目**(異論があればゲート1で言ってもらう)。

- **Q9 投球のテンポ**: 約 3.6 秒/球(v2 は約 2.7 秒)。短くする余地は `gauge.ringMs`。
- **Q10 実機で足りないとき**: 自動で品質ティアを下げる(T3 でも p95 > 33ms ならログに警告)。ゲート2でユーザーが最終判断する。
- **Q11 ユーザーが指す「パワプロ」の作品・端末・持ち方・音を出して遊んだか**: T1 の依頼文で一緒に聞く(Q3・Q7 の判断材料)。
