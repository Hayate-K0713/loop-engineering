## E2E(Playwright。D2)

既存の 24 件を v3 の操作・DOM に合わせて更新し、次を追加する。**SwiftShader では実入力が 0.2〜1 秒以上遅れる**ので、時間窓を狙うテストは「ページ内で入力の `event.timeStamp`・飛行開始・D を記録し、アプリと同じ計算で有効試行だけを検証、無効は次の投球で再試行(最大 5 回)」にする([[swiftshader-playwright-input-latency]])。**前提**: tutorial 以外の spec は `addInitScript` で既読・球数ヒントの設定を入れる。試遊ログは `DEV` で常に有効なので、「入口が無い」確認は preview ビルドの別 project。

1. **タップでスイング(タッチ)**: ドラッグしてカーソルを動かし、指を離してから(または 2 本目の指で)タップ → `data-timing` が出る。判定時刻が**押下の時刻**であること(有効試行のとき `dtMs` を検証)。v2 のタップの E2E を維持。
2. **タップが通らない場合の理由とヒント**: 長押し(180ms 超)・移動(10px 超)でスイングにならず、`tap-too-long`/`tap-moved` がログに残り、ヒントが最大 3 回出る。
3. **見逃し(タップしない)**: ストライクをタップせずに通過させると見逃しになる。**到達の後のタップは無視される(空振りにならない)**。到達の前に押して離しが保留内のタップは「遅い」の空振りになりうる。
4. **スキップに使った指**: スキップして指を置いたまま離してもスイングにならない(`held-release`)。離してもう一度タップ、または 2 本目の指でスイングできる。
5. **追加の指・スイングボタン・Space**: v2 のテストを維持。
6. **予告とリング**: `data-guide="exact"`(ふつう)・`fade`(むずかしい)。リング半径が減る。
7. **投球**: PC・キー・ボタン(2 回目はゲージ開始から 250ms 以上後)で 1 球投げられ `data-pitch-quality` が出る。自動投球で失投になり試合が止まらない。ダブルクリックで失投にならない。守備の入力面の `touch-action` が `none`。守備でスキップに使った指を離してもゲージが始まらない。
8. **チュートリアル**: 初回に出て閉じる(タップ方式の文言)。表示中は投球が始まらず、Space/Enter でスキップされず「つぎへ」がキーで押せる。
9. **音**: `AudioContext` を計数スタブに差し替え、最初の操作(`pointerup`/`click`/`keydown`)の後に `unlock`、1 球で cue が呼ばれる。ミュートで呼ばれない。既定が ON。音質は自動では検証できない。
10. **試遊ログ**: スイングごとに記録が増え、要約と `<textarea>` の JSON が出る。`localStorage` が例外でも 1 試合が通る。clipboard を無効化しても取り出せる。preview ビルドでは入口が無い。
11. **幾何**: 縦長 3 高さ+デスクトップ+タブレットの打撃・守備(バー ≤ 135/140px、格子がバーに掛からない、打者の頭の右端(ヘルメット込み)≤ 115px、ゾーンがオーバーレイと 4px 以上離れる)。`ZoneFeedback` が `zoneRect` に重なって出る。`index.html` に viewport meta がある。
12. **キャラクター**: 結果に応じて役割ごとの表情が切り替わる(`data-expr-pitcher`・`data-expr-batter`)。ヒットで走者が進塁し(`data-runner-*`)内野カメラへ移る。三振・ヒットでワイプが出て(`data-wipe`)、`?tier=3` で出ない。`?tier=<n>` で品質ティアが固定される(`data-quality-tier`)。ワイプの矩形が 390×664 でも HUD と重ならない。
13. **回帰**: 1 イニング通し・WebGL 不可・スキップ・Enter/Space 長押しで再試合しない・`home.spec.ts`。seed は A14・B3・D1 の後に再探索する。
14. **リプレイ(最大)**: ホームランの後に「リプレイ」ボタンが出る(`data-replay="available"`)。押すと再生され(`data-replay="active"`)、**スコア・カウント・アウトが再生の前後で変わらない**。再生中は打撃/投球の入力が無効で、タップで終了する。`?tier=3` ではボタンが出ない。自動再生の設定を ON にすると HR の後に自動で再生される(既定 OFF)。
15. **時間帯(最大)**: 既定の「自動」で 1〜3 回 `data-time-of-day="day"`、4〜6 回 `evening`、7 回〜 `night`。`?tod=night` で固定。切替が飛行中に起きない。
16. **観客・球場(最大)**: `data-crowd-count` がティアのとおり [480, 240, 96, 0]。ホームランで観客の `excitement` が上がる(`data-crowd-excitement` が 0.5 以上)。`?tier=3` で観客が 0。イントロが試合開始に出て、タップでスキップできる。
17. **スライディング・ベースカバー(最大)**: 二塁走者が単打で生還するプレーで `data-runner-slide` が出る場合があり、走者の最終位置・得点が結果と一致する。併殺でベースカバーの `data-cover-*` が出る。
18. **スコアボード(最大)**: `data-scoreboard` の値が HUD のスコア・イニング・カウントと一致する。

## 「人間が遊んで打てるか・見て『それっぽい』か」の検証手順と、人間に渡すタイミング

1. **ボット(代理)**: 打撃・投球ボットの帯を満たす。**検出力テスト(E1)で前回の不合格を再現できること**・**悲観シナリオ(E10)と失敗の型(E11)**が前提。段階 E の後に再実行する(E12)。
2. **T1 — 中間試遊(段階 A の完了直後 = A13。段階 E・B・C・M の前。ゲート1で実施が決定)**: 試遊ビルド(`VITE_PLAYTEST=1`)を人間に渡す。**打撃 20 打席(約 60 球)**を遊び、画面の試遊ログ(JSON)をコピーして貼る(キャラクターは v2 のまま・守備・演出・音は未実装。**操作は v2 と同じタップ方式で、予告・リング・ロックオンが加わった版**)。診断(下の表)で原因を切り分け、ロックオン強度・予告・遅延補正・ボットの較正に反映する(A14。必要なら A1・A2・A4 を直す。A2 の修正が必要なときは E3 の着手前に直す)。
3. **T1b — キャラクターの確認(段階 E の完了直後 = E11。ゲート1で実施が決定)**: E11 のスクリーンショットと試遊ビルドを人間に渡し、「パワプロっぽいか」と足りない点を聞く(`AskUserQuestion`)。足りなければ E の調整を B の前に入れる。
4. **T1c — 球場・リプレイの確認(段階 M の完了直後 = M13。任意。本体の「未解決の疑問」)**: M13 のスクリーンショット(昼/夕/夜・スタンド・リプレイ・スライディング・イントロ)と試遊ビルドを人間に渡し、見た目と負荷(カクつき)を聞く。足りなければ D3 の調整に回す。
5. **T2 — 最終試遊(`/test` 完了後 = ゲート2)**: 必須。**打撃 20 打席(約 60 球)と守備 20 球**を遊ぶ。合格の目安は、**人間の主観**(「打てた・投げられた・パワプロっぽい」/「微妙」/「打てない・違う」)と、ログの客観値(**最初の 20 打席**の目安: コンタクト率 ≥ 55%、ストライクを振る率 ≥ 70%、離す時刻の SD ≤ 100ms、距離の中央値 ≤ 60px、**「押したのにスイングにならなかった」(`tap-too-long` + `tap-moved`)が押下の 15% 以下**、fps の p95 ≤ 33ms(下回る場合は品質ティアの切替の記録を見る))。**主観が「打てない」「パワプロじゃない」なら、ボットが合格していても不合格**とし、ログの診断表で原因を特定して `/design` か `/implement` に戻る。
6. 試遊環境の確認: ログの端末情報と縮小表示の警告で、どの画面で遊んだかを記録する。公開アーティファクトの HTML には viewport meta がある(調査で確認済み)ので、`index.html` の viewport meta を E2E で固定するにとどめる。取り出しは画面の `<textarea>` が必ず動く。
