**ボットの前提の根拠(E 群)**: 反応時間 200〜250ms・見た目の到達の偏り(+130ms で位置が完璧でも 39% が空振り)・人間の打撃タイミングの精度は調査 batting.md 2.5・出典(Smeets ほか)と v2 診断。**リング有りの `biasMs` などの v3 固有の値は仮定**で、悲観シナリオ(E10)で楽観に偏っていないかを見る。T1・T2 の試遊ログで較正する。帯はボットの出力の期待であり、人間の手触りの保証ではない([[game-feel-needs-playability-check]])。

## 構造検査(`/test`・`code-reviewer` が grep)

(1) `from "three"` が `render/` のみ。(2) `render/` が `../model`・`../hooks`・`../ui`・`../audio` を import しない。(3) `model/` が `three`・`react`・`../render`・`../hooks`・`../ui`・`../audio` を import しない。(4) `AudioContext`・`webkitAudioContext` が `audio/` のみ、`audio/` が `types/` 以外を import しない。(5) `model/world/` と `model/character/` に `Math.random`・`Date`・`performance`・`window`・`document` が無い。(6) `usePointerInput` が `routeStage*` の戻り値で分岐し、`holding` を直接参照していない。(7) スイング時刻を `performance.now()` の差だけで求めていない(`swingAtMs`・`eventElapsedMs` 経由)・ゲージ時刻も `event.timeStamp` 経由。(8) `model/sim/` を import しているのが `*.test.ts` だけ。(9) `skip()` が reducer に触れない・`stage === null` でも plan を進める。(10) `getBoundingClientRect` を使う hooks が `useSafeArea.ts`・`useStage3d.ts`・`usePointerInput.ts` に限られる。(11) `PLAYTEST_ENABLED` が偽のとき `localStorage` に書く経路が無い。`localStorage` への直接アクセスが `createSafeStore` を通す箇所以外に無い。(12) 「パワプロ」「パワフル」が 0 件。(13) `ui/` が `../audio` を import しない。**(14) `render/character/` が `BufferGeometryUtils`(`three/examples`)・`CanvasTexture`・`document` を使わない。`SkinnedMesh`・`Skeleton`・`Bone` は `render/character/` の中だけで生成される。(15) `model/character/` が `three` を import しない・キャラクターの見た目のデータ(`CharacterLookData`)が `types/` 経由でのみ `render/` に渡る。`render/character/parts.ts` が `render/` 以外から import されない。**

## E2E(Playwright。D2)

既存の 24 件を v3 の操作・DOM に合わせて更新し、次を追加する。**SwiftShader では実入力が 0.2〜1 秒以上遅れる**ので、時間窓を狙うテストは「ページ内で入力の `event.timeStamp`・飛行開始・D を記録し、アプリと同じ計算で有効試行だけを検証、無効は次の投球で再試行(最大 5 回)」にする([[swiftshader-playwright-input-latency]])。**前提**: tutorial 以外の spec は `addInitScript` で既読・球数ヒントの設定を入れる。試遊ログは `DEV` で常に有効なので、「入口が無い」確認は preview ビルドの別 project。

1. **離す=スイング(タッチ)**: ドラッグし、飛行中に離す → `data-timing` が出る。有効試行のときだけ `dtMs` を検証。
2. **持ち替えは捨てる**: イベント時刻が D−300ms より前の離しでスイングにならない(ヒント)。**D−300〜D−80ms は「早い」の空振り**(窓外)。
3. **見逃し(指を離さず待つ)**: イベント時刻 D+300 に離す → 見逃し。**D+200 → スイング扱い(遅い。`atMs = D+130` は窓 ±150ms の内なので当たることもある)**。D+400 → 見逃し。
4. **持ち越しの指**: スキップして指を置いたまま次の球で離す → スイング。
5. **追加の指・スイングボタン・Space**: v2 のテストを維持。
6. **予告とリング**: `data-guide="exact"`(ふつう)・`fade`(むずかしい)。リング半径が減る。
7. **投球**: PC・キー・ボタン(2 回目はゲージ開始から 250ms 以上後)で 1 球投げられ `data-pitch-quality` が出る。自動投球で失投になり試合が止まらない。ダブルクリックで失投にならない。守備の入力面の `touch-action` が `none`。
8. **チュートリアル**: 初回に出て閉じる。表示中は投球が始まらず、Space/Enter でスキップされず「つぎへ」がキーで押せる。
9. **音**: `AudioContext` を計数スタブに差し替え、最初の操作(`pointerup`/`click`/`keydown`)の後に `unlock`、1 球で cue が呼ばれる。ミュートで呼ばれない。音質は自動では検証できない。
10. **試遊ログ**: スイングごとに記録が増え、要約と `<textarea>` の JSON が出る。**`localStorage` が例外でも 1 試合が通る**。clipboard を無効化しても取り出せる。preview ビルドでは入口が無い。
11. **幾何**: 縦長 3 高さ+デスクトップ+タブレットの打撃・守備(バー ≤ 135/140px、格子がバーに掛からない、**打者の頭の右端(ヘルメット込み)≤ 115px**、ゾーンがオーバーレイと 4px 以上離れる)。**`ZoneFeedback` が `zoneRect` に重なって出る(接触後も位置が変わらない)**。`index.html` に viewport meta がある。
12. **キャラクター**: **結果に応じて役割ごとの表情が切り替わる**(`data-expr-pitcher`・`data-expr-batter`。三振で打者 `sad`・投手 `cheer`、ヒットで打者 `joy` など)。ヒットで走者が進塁し(`data-runner-*`)内野カメラへ移る。三振・ヒットでワイプが出て(`data-wipe`)、`?tier=3` で出ない。`?tier=<n>` で品質ティアが固定される(`data-quality-tier`)。**ワイプの矩形が 390×664 でも HUD と重ならない**。
13. **回帰**: 1 イニング通し・WebGL 不可・スキップ・Enter/Space 長押しで再試合しない・`home.spec.ts`。seed は A14・B3・D1 の後に再探索する。

## 手動確認(ゲート2の前に `tester` が実施し、人間が実機で再確認)

① スマホ縦で、打撃・守備の構図(打者が小さく端・ゾーンが中央・投手が顔と表情の読める大きさ)、予告の点とリング、ボールの見え方(ハロー)。② 1本指で「スライド→離す」で振れる、見逃すときに指を離さず待てる、持ち替えが誤爆しない、スキップした指をそのまま離せる。③ 守備でゾーンをなぞって狙い、リングに合わせてタップでき、狙いと着弾の重ね表示(ナイス・ふつう・失投の見え方)。スクロール・長押しのメニューが出ない。④ バナー・ヒットストップ・位置ずれ表示(DOM のミニ図が接触後も 900ms 見え、ボールを隠さない)。⑤ 音・振動・ミュート。⑥ チュートリアル。⑦ **キャラクター: 顔・8 表情・髪・ヘルメット・背番号・20 人の個性・フォーム・走者の進塁・送球・ワイプ・品質ティアの切替**。⑧ ボットの出力(E・F 群)を完了報告に貼る。⑨ **実機の試遊ログ**。

## 「人間が遊んで打てるか・見て『それっぽい』か」の検証手順と、人間に渡すタイミング

1. **ボット(代理)**: 打撃・投球ボットの帯を満たす。**検出力テスト(E1)で前回の不合格を再現できること**・**悲観シナリオ(E10)と失敗の型(E11)**が前提。段階 E の後に再実行する(E12)。
2. **T1 — 中間試遊(段階 A の完了直後 = A13。段階 E・B・C の前)**: 試遊ビルド(`VITE_PLAYTEST=1`)を人間に渡す。**打撃 20 打席(約 60 球)**を遊び、画面の試遊ログ(JSON)をコピーして貼る(キャラクターは v2 のまま・守備・演出・音は未実装)。診断(下の表)で原因を切り分け、ロックオン強度・予告・遅延補正・見逃し/持ち替えの規則・ボットの較正に反映する(A14。必要なら A1・A2・A4 を直す。**A2 の修正が必要なときは E3 の着手前に直す**)。**ゲート1で承認を得る**(Q8)。
3. **T1b — キャラクターの確認(段階 E の完了直後 = E11)**: E11 のスクリーンショット(打撃・守備・表情・個性・フォーム・走者・ワイプ)と試遊ビルドを人間に渡し、「パワプロっぽいか」と足りない点を聞く(`AskUserQuestion`)。足りなければ E の調整(E2 の顔・E5 の造形・E3 のフォーム)を B の前に入れる。
4. **T2 — 最終試遊(`/test` 完了後 = ゲート2)**: 必須。**打撃 20 打席(約 60 球)と守備 20 球**を遊ぶ。合格の目安は、**人間の主観**(「打てた・投げられた・パワプロっぽい」/「微妙」/「打てない・違う」)と、ログの客観値(**最初の 20 打席**の目安: コンタクト率 ≥ 55%、ストライクを振る率 ≥ 70%、離す時刻の SD ≤ 100ms、距離の中央値 ≤ 60px、無視された離しのうち `late` + `regrip` ≤ 20%、`expired` ≤ 3%、fps の p95 ≤ 33ms(下回る場合は品質ティアの切替の記録を見る))。**主観が「打てない」「パワプロじゃない」なら、ボットが合格していても不合格**とし、ログの診断表で原因を特定して `/design` か `/implement` に戻る。
5. 試遊環境の確認: ログの端末情報と縮小表示の警告で、どの画面で遊んだかを記録する。公開アーティファクトの HTML には viewport meta がある(調査で確認済み)ので、`index.html` の viewport meta を E2E で固定するにとどめる。取り出しは画面の `<textarea>` が必ず動く。

**診断表(実機の試遊ログ)**

| 症状(ログの値) | 疑う原因 | 打つ手 |
| --- | --- | --- |
| 離す時刻の平均 `dtMs` が +80ms 以上 | 到達の知覚の偏り・遅延補正の不足 | 遅延補正(70ms)の見直し、リングの見せ方 |
| `dtMs` の SD が 100ms 以上 | リズムが取れない(合図が弱い) | リングの太さ・音・球速 |
| 距離の中央値が 60px 以上 | カーソルが間に合わない・ロックオンが弱い | ロックオン強度・ドラッグの感度 |
| 離した入力が `touch-second`/`button` ばかり | 1 本指の「離す=スイング」が使われていない | チュートリアルの見直し |
| ボールを振る率が高い | 予告が読めていない | 予告の見せ方 |
| 無視された離しの `late` が多い | 見逃し時に指を離してしまう | ヒント・チュートリアル・締切の見直し |
| 無視された離しの `regrip` が多い | 持ち替えの多用 | ガード時刻・ヒントの見直し |
| **無視された離しの `expired` が多い** | 描画の遅れで窓内の離しが受理できていない | 描画負荷(品質ティア・影)、保留 `aimGraceMs` の見直し |
