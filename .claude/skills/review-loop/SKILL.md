# review-loop: 独立レビュアーによる自動レビューループ(最大2ラウンド)

**このレビューは人間を介さない自律的なチェックであり、人間確認ゲートを代替・追加するものではない。** レビューが完了しても承認されたことにはならず、続けて(またはそのまま)人間確認ゲートに進む。

呼び出し元が渡すパラメータ:

- `artifact`: レビュー対象(設計ドキュメントのパス、または実装差分の範囲・参照ドキュメント)
- `reviewer-agent`: 作成者とは別のレビュー専任サブエージェント(例: `design-reviewer`・`code-reviewer`)。**作成者自身にレビューを兼任させない**(書いた本人が自分のミスに気づけない状態を避ける)。
- `author`: 修正を行う担当(人間、または`designer`/`implementer`等の委譲先)

## 前提: レビュアーの独立性

`reviewer-agent`は自分では成果物を書き直さない。指摘のみを行い、修正は`author`に委ねる。可能であれば`reviewer-agent`は作成時とは**異なるモデル**を使う(同じモデルで書いてレビューすると、そのモデル特有の盲点がレビューでもすり抜けやすいため)。

## 手順

1. **ラウンド1。** `reviewer-agent`に`artifact`(と関連する前段の成果物、例: 設計レビューなら対応する調査ドキュメント)を渡してレビューを依頼する。判定は`PASS`または`MAJOR`。
2. **`PASS`の場合。** 指摘(あれば軽微なもの)を`artifact`内の記録欄に簡潔に記録し、ループを終了する。呼び出し元の次のステップ(人間確認ゲート等)に進む。
3. **`MAJOR`の場合。** `author`が指摘に基づいて`artifact`を修正し、同じ`reviewer-agent`に再レビューを依頼する(ラウンド2)。
4. **ラウンド2の結果に関わらず、それ以上は自動でループしない(最大2ラウンド)。** ラウンド2で`MAJOR`が残った場合、その指摘を隠さず、**直後の人間確認ゲートの提示内容に明記**し、最終判断を人間に委ねる。
5. 実施したラウンド数・各ラウンドの判定・主な指摘を、`artifact`の記録欄(例:「設計レビュー結果」「コードレビュー結果」)に簡潔に記録する(例:「設計レビュー: 2ラウンド、最終判定PASS」)。

## よくある間違い

| 誤り | 実際 |
|------|------|
| 作成者自身にレビューを兼任させる | `reviewer-agent`は必ず作成者とは別のサブエージェントにする |
| ラウンド2以降もMAJORが残るたびに何度も再レビューする | 最大2ラウンドで打ち切り、残った指摘は人間確認ゲートへ引き継ぐ |
| レビューがPASSしたらそのまま人間確認ゲートを省略する | レビューは人間確認ゲートの代替ではない。PASSでも通常どおりゲートに進む |
| `reviewer-agent`自身に修正まで行わせる | 修正は必ず`author`(元の作成者または委譲先)が行う。`reviewer-agent`は指摘のみ |
| ラウンド2でMAJORが残ったのに記録・報告に明記しない | 未解決のMAJORは必ず次の人間確認ゲートの提示内容に含める |
