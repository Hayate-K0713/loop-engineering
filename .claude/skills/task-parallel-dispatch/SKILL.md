# task-parallel-dispatch: タスク分割・並列dispatch

呼び出し元(オーケストレーター)は自分で作業を実行せず、タスクへの分割・依存関係の整理・並列dispatch・進捗確認・完了報告後のコミット取りまとめに徹する。**タスクが1つしかない場合、または依存が強く並列化の余地がない場合でも、サブエージェントへの委譲そのものは省略しない。**

呼び出し元が渡すパラメータ:

- `topic-slug`: タスクの`subject`に付与するプレフィックス(このプロジェクトのタスクリストはトピックをまたいで1つの共有リストのため、自分のトピックのタスクだけを識別する必要がある)
- `worker-agent`: 実行を委譲するサブエージェント名(例: `implementer`)
- 分割対象の作業項目(通常は設計ドキュメントの実装ステップ)

## 手順

1. **タスク分解。** 作業項目を、対象ファイル・やること・参照すべきドキュメントの節を明示すれば、この会話の文脈を持たない`worker-agent`だけで着手できる粒度に分解する。1項目が大きすぎる場合はさらに分ける。
2. **`TaskCreate`。** 各タスクの`subject`先頭に`[<topic-slug>]`を付与し、`metadata`に`{"topic": "<topic-slug>"}`を設定する。作成前に`TaskList`で既存タスクと重複しないか確認する。
3. **依存関係の整理。** `TaskUpdate`の`addBlockedBy`/`addBlocks`で明示する。**同じファイルを変更する複数のタスクは並列化の対象にせず、依存関係として順序づける。** 依存がなく、かつ変更対象ファイルが重ならないタスクだけが並列化の候補になる。
4. **ウェーブの組成。** `TaskList`を呼び、**`subject`の`[<topic-slug>]`プレフィックスで自トピックのタスクだけに絞り込んだうえで**、「pending・未所有・blockedByが空」のタスクをまとめて1つの「ウェーブ」とする。他トピックのタスク(別のプレフィックスが付いているもの)には触れない。
5. **並列dispatch。** そのウェーブ内のタスクを、**同一メッセージ内で`worker-agent`を複数回呼び出して並列実行する**(Agent toolを1レスポンス内で複数回呼ぶ)。各呼び出しには対象の`taskId`とタスク内容、参照ドキュメントへのパスを明示する。
6. **状態更新。** 各`worker-agent`は着手前に`TaskUpdate`で自タスクの`owner`を自分自身に設定し`status: in_progress`にする。完了したら`status: completed`にする。**未完了・部分実装・未解決のエラーが残る場合は`completed`にせず、`in_progress`のまま理由を添えて報告する。**
7. **並列dispatch中の`worker-agent`は`git commit`を自分では行わない。** 同一worktree内で複数プロセスが同時にコミットすると競合するため、ファイルの編集のみ行い、変更内容を呼び出し元に報告する。呼び出し元は、各タスクの完了報告を受けるたびにそのタスク分をコミットする(意味のある単位で1タスク1コミットが目安)。これは実装ではなく記録作業なので、呼び出し元自身が行ってよい。
8. **並列dispatch中は`worker-agent`も共有メモリ(`docs/memory/`等)へ直接書き込まない。** 複数エージェントが同時に書き込むと競合・上書きが起きるため、再利用可能な知見は完了報告に「メモリ候補」として含めるに留め、実際の書き込みはウェーブ完了ごとに呼び出し元が集約して1回で行う。
9. **次のウェーブへ。** 1ウェーブが完了したら`TaskList`で(自トピックのタスクに絞って)状態を確認し、次に着手可能になった(blockedByが解消された)タスクで次のウェーブを組み、手順5〜8を繰り返す。自トピックの全タスクが`completed`になるまで続ける。

## 完了条件

- `TaskList`を自トピックのプレフィックスで絞り込んで確認し、すべてのタスクが`completed`(または明確に不要と判断され`deleted`)になっている
- 変更内容がworktree内でコミットされている(呼び出し元によるタスク単位のコミット)

## よくある間違い

| 誤り | 実際 |
|------|------|
| タスクが1つだけなので自分で実装してしまう | タスクが1つでも`worker-agent`への委譲を省略しない(呼び出し元のポリシーで「自分で実装しない」が定められている場合は特に例外なく従う) |
| 同じファイルを変更する2タスクを並列dispatchする | 依存関係として順序づけ、並列化の対象から外す |
| `worker-agent`が完了報告前に自分でコミットする | コミットは呼び出し元がタスク単位で行う。並列dispatch中の`worker-agent`はファイル変更のみ |
| 他トピックのタスクも一緒に`TaskList`で拾ってしまう | 必ず`[<topic-slug>]`プレフィックスで絞り込む |
